ДИАГНОСТИКА КРИПТОПРО ДЛЯ CSPSIGNER

Этот пакет помогает сравнить сбой CAdESCOM.Store.Open в независимых
средах. Он не является исправлением программы подписания.

КАК ЗАПУСТИТЬ
1. Распакуйте все четыре файла в одну доступную для записи папку.
2. Войдите в Windows под той же учётной записью, где не работает
   программа подписания. Права администратора не нужны.
3. Дважды нажмите Check-CryptoPro.cmd и дождитесь окончания.
4. Пришлите файл ActSigner-diagnostics.txt из этой же папки.
   Результат также выводится в окно; оно остаётся открытым до нажатия
   клавиши. При повторном запуске предыдущий отчёт перезаписывается.

Каждая внешняя попытка ограничена 30 секундами и запускается в новом
процессе. Ошибка или зависание одной попытки не отменяет остальные.
Обычно проверка проходит быстро. Если зависают все попытки, на Windows
x64 весь запуск может занять около 13 минут. При закрытии окна раньше
времени уже записанная часть отчёта остаётся в файле.

ЧТО ПРОВЕРЯЕТСЯ
- Версии Windows, Windows PowerShell, CLR и разрядность процессов.
- Регистрация CAdESCOM.Store отдельно в 32- и 64-разрядном представлении
  реестра, имя COM DLL и её числовые версии. Полный путь DLL не выводится.
- Количество сертификатов .NET CurrentUser/My с флагами
  ReadOnly | OpenExistingOnly.
- Прямые вызовы CAdESCOM из PowerShell и отдельно из CScript/JScript
  для доступных архитектур Windows, с новым объектом на каждую попытку:

  CurrentUserReadOnly        Open(2, 'My', 0)
  DefaultOpen                Open()
  CurrentUserLocationOnly    Open(2)
  CurrentUserMaximumAllowed  Open(2, 'My', 2)
  MemoryReadOnly             Open(0, 'My', 0)
  ContainerReadOnly          Open(100, 'My', 0)

Open() использует документированные значения по умолчанию (2, 'My', 0).
Сравнение с явными аргументами помогает проверить передачу параметров.
Режим 2 означает максимальные доступные права при открытии; в этой
проверке после открытия читается только Count и вызывается Close.
Проба MemoryReadOnly обращается к хранилищу в памяти.

Файл отчёта содержит этапы, числовые коды ошибок, типы исключений .NET,
stdout/stderr работников и количество сертификатов. Строки записываются
сразу, кодировка UTF-8 с BOM. Полные сообщения исключений не выводятся:
в них могут оказаться личные пути или данные поставщика криптографии.

Пакет не читает имена владельцев, отпечатки и содержимое сертификатов,
не выводит имена контейнеров ключей, не подписывает файлы, не запрашивает
и не сохраняет PIN, не экспортирует ключи. Он не добавляет и не удаляет
сертификаты, не устанавливает компоненты и не меняет регистрацию COM
или постоянные настройки Windows. Создаётся только текстовый отчёт.

РАЗБОР РЕЗУЛЬТАТОВ
ERROR, TIMEOUT и SKIP являются результатами проверки. Они сами по себе
не доказывают неисправность носителя. Различие версий DLL x86 и x64
также не является самостоятельным признаком ошибки. Для выводов нужно
сравнить этапы и коды в соответствующих попытках.

ТРЕБОВАНИЯ
Windows PowerShell 5.1 и Windows Script Host (CScript), если он доступен.
Отсутствующий или заблокированный CScript не нужно включать ради теста:
это отразится в отчёте, остальные попытки продолжатся. PowerShell
запускается без профиля; Bypass в команде относится только к запущенному
процессу и не меняет постоянную политику выполнения сценариев.

Check-CryptoPro.ps1, Check-CryptoPro.js и Check-CryptoPro.cmd должны
оставаться рядом. Пробелы, кириллица и символ & в пути поддерживаются.

Перед выдачей проверены синтаксис, передача аргументов, запись отчёта,
таймаут с продолжением и сценарии ошибок на имитаторах COM. Реальный
Windows COM в среде подготовки пакета недоступен; его проверка является
назначением этого пакета.
