ACTSIGNER: ПАКЕТНОЕ ПОДПИСАНИЕ PDF-АКТОВ ЧЕРЕЗ КРИПТОПРО
Версия 1.5.1

ИСПРАВЛЕНИЕ 1.5.1
Состав подписантов CMS, математика точных байтов PDF и доверие к
сертификатам проверяются отдельно. Истёкший чужой сертификат не мешает
добавить отдельную подпись, если состав и математика подтверждены.
Полная проверка выбранного сертификата и новой подписи сохранена.
На Windows 11 с CSP 5.0.13300 и CAdESCOM 2.0.15500 проверены реальная
ГОСТ-подпись, полная проверка, повтор без ключа, два подписанта,
изменённый PDF и повреждённый SIG. Исходные хеши PDF/SIG сохранились.
Приватные документы и диагностические отчёты в репозитории отсутствуют.

Полное описание, правила файлов, ограничения, журнал, тесты и FAQ:
README.md в этой же папке
https://github.com/Alox1d/act-signer#readme

ТРЕБОВАНИЯ
Windows с рабочим столом и Windows PowerShell 5.1, Windows Script Host
(cscript.exe с JScript), КриптоПро CSP, локальные компоненты CAdESCOM,
действующий сертификат ГОСТ Р 34.10-2012 и доступ к его закрытому ключу.
Для USB-токена нужен совместимый драйвер. В VM компоненты и носитель
должны быть доступны именно гостевой Windows.
Компоненты КриптоПро: https://www.cryptopro.ru/products/cades/downloads
Документация: https://docs.cryptopro.ru/cades/plugin

ЗАПУСК
1. На GitHub откройте Code > Download ZIP и полностью распакуйте архив
   в одну папку Windows. Ссылка на репозиторий указана выше.
2. Откройте Start.cmd. Не запускайте программу прямо из ZIP-архива.
3. Выберите папку с актами и проверьте режим сохранения.
4. Выберите сертификат; для повторного поиска нажмите Обновить.
   Данные сертификата и ошибки открываются кнопкой Подробнее.
5. Выберите формат имени подписи (по умолчанию signature_<фамилия>.sig).
   Нажмите Найти акты, проверьте список и отметки.
6. Нажмите Проверить и подписать. Обработка продолжится в консоли.
   PIN вводится только в штатном окне КриптоПро или токена.
7. Дождитесь результата и пути к журналу.

ПРОВЕРКА СОСЕДНИХ ПОДПИСЕЙ 1.5.1
Рядом с каждым актом проверяются .sig, .p7s, .p7m и .sgn с любыми именами.
Для отдельной папки проверяется также папка рядом с выходным PDF.
Статусы Проверить подписи (N) и Проверить .my.sig обозначают кандидатов.
Существующую .my.sig можно отметить для проверки; перезаписи не будет.

Подтверждённая математическая подпись точного PDF выбранным сертификатом
даёт already_signed без ключа и новой подписи. Учитываются все реальные
SignerInfo и однозначно соответствующие сертификаты, включая идентификатор
ключа. ФИО, имя файла и сертификаты цепочки не заменяют проверку подписанта.

Если все математические подписи подтверждены и принадлежат другим
сертификатам, можно добавить свою. Математический успех не подтверждает
доверие, сроки цепочки, отзыв или время подписания. Неопределённый состав
или возможная собственная подпись без подтверждения блокируют этот акт.
Ошибки отдельных актов не мешают независимым. Отмена пользователем и
неисправный общий криптографический сеанс останавливают пакет отдельно.

Поддержаны отсоединённые CMS/PKCS7 в DER/BER, Base64 или PEM CMS/PKCS7.
Проверка соседей использует Windows CryptoAPI без закрытого ключа.
Вложенный документ или повреждённый формат требуют ручного разбора.
Лимит PDF/SIG - 64 МиБ, подписантов - 4096, повторного хеширования - 512 МиБ.
Сеанс подписи создаётся только при необходимости новой подписи.
Полные правила и ограничения: README.md.

ПАУЗА КОНСОЛИ: ИСПРАВЛЕНИЕ 1.4
Если в заголовке чёрного окна есть Выбрать или Select, нажмите Esc.
Режим выделения текста может блокировать вывод и останавливать пакет.
Версия 1.4 временно отключает случайное выделение мышью (QuickEdit)
и восстанавливает прежний режим при завершении. Постоянные настройки
Windows не меняются. Для вручную включённого выделения также нажмите Esc.

Строка [1/6] означает начало первого акта. Сообщение Создана и проверена.
появляется после сохранения подписи и записи результата в журнал.
Если после Esc ожидание продолжается, проверьте окно PIN через Alt+Tab
и последнюю строку консоли. Существующие .my.sig не перезаписываются.

ИНТЕРФЕЙС 1.3
Список актов занимает свободное место окна. Счётчик и кнопки подписания
остаются внизу; сведения сертификата вынесены в окно Подробнее.
Строка отдельной папки видна при отключённом режиме рядом с исходниками.

На первом запуске включено Сохранять рядом с исходниками: подпись каждого
акта попадёт в его собственную подпапку. В отдельной папке сохраняется
структура подпапок, копируются выбранные акты и предусмотренные файлы.
Последние папки и явно выбранный режим запоминаются, в том числе при
закрытии окна без подписания. Настройки: %LOCALAPPDATA%\ActSigner\settings.json.

Поиск рассчитан на Акт_оказанных_услуг.pdf и Акт_выполненных_работ.pdf,
по одному пробелу или подчёркиванию между словами, с необязательным
номером в скобках перед .pdf. Точное правило и примеры есть в README.md.
Другие имена PDF и печатные формы как акты не подписываются.

По умолчанию создаётся signature_<фамилия>.sig, например signature_ivanov.sig.
Фамилия берётся из сертификата и переводится в латиницу. Если её нет,
используется cert_<12 символов отпечатка>. В окне можно запомнить формат
с именем акта и фамилией либо прежний .my.sig. Конфликт одинаковых имён
нескольких актов блокируется до ключа, существующие файлы не перезаписываются.
Подпись отдельная: для проверки нужны и исходный PDF, и файл подписи.
Исходные PDF не редактируются. Лимит каждого входного файла и подписи:
64 МиБ. Существующий целевой SIG по-прежнему защищён от перезаписи
и проверяется, если акт отмечен. Соседние подписи проверяются по
правилам 1.5.1, описанным выше.
Ошибка акта не останавливает независимые. Уже сохранённые результаты остаются;
при поздней ошибке возможен неполный комплект копий.
Журнал находится в <папка результата>\_ActSigner_logs.

ДИАГНОСТИКА
При ошибке открытия хранилища запустите diagnostics\Check-CryptoPro.cmd
под тем же пользователем Windows. Отчёт ActSigner-diagnostics.txt будет
рядом с диагностическими скриптами. Инструкция: diagnostics\README.txt.
Диагностика сравнивает PowerShell и CScript в доступных разрядностях,
не создаёт подписи и не экспортирует ключи. Каждая попытка ограничена
30 секундами; ошибка одной попытки не отменяет остальные.

ПЕРЕД ПУБЛИКАЦИЕЙ ОШИБКИ
Просмотрите и обезличьте отчёт. Не отправляйте в публичный Issue ключевые
контейнеры, PIN, .pfx/.p12, реальные документы, подписи или полный CSV:
в журнале есть пути, отпечаток сертификата, хеш документа и текст ошибки.
Скриншоты окна сертификата также могут содержать персональные данные.

Перед рабочим использованием требуется проверить полный цикл подписи
в целевой Windows на несекретном тестовом документе. Тесты файловой логики
и локальных вспомогательных функций не подтверждают работу настоящего
CAdESCOM и токена.

ТЕСТЫ
Локальный криптографический тест прошёл проверки PowerShell и 21 сценарий
JScript с имитацией COM. Для JScript-части теста нужен Node.js; без него
эта часть явно пропускается. Для запуска ActSigner Node.js не требуется.
Нативный тест Windows Forms проверяет список актов, выбор, режим папок
и диагностику на вымышленных данных в окнах 1000x700 и 900x600.
Тест консоли проверяет временное отключение и восстановление QuickEdit
в отдельном процессе Windows. Криптография ему не требуется.
Команды, состав тестов и пределы проверки описаны в README.md.

АВТООБНОВЛЕНИЕ 1.5.0

Запускайте Start.cmd из этой распакованной папки. Он открывает готовую
локальную версию, а проверку GitHub выполняет в отдельном фоновом процессе.
Новая версия после загрузки и проверки включается при следующем запуске.
Работающий пакет подписания обновлением не прерывается.

Стабильные релизы: https://github.com/Alox1d/act-signer/releases/latest
Для перехода с 1.4 нужно один раз распаковать новый ZIP и запустить новый
Start.cmd. В дальнейшем вручную заменять программу для обновления не нужно.
Без интернета, при ошибке скачивания или проверки запускается локальная
версия. Проверяются состав, размеры и SHA-256 файлов. Это проверка целостности
относительно релиза из GitHub по HTTPS, а не отдельная подпись издателя.

Папки версий: %LOCALAPPDATA%\ActSigner\updates
Настройки папок: %LOCALAPPDATA%\ActSigner\settings.json
Акты, подписи, ключи и настройки обновлением не изменяются.

В PowerShell из папки программы можно запустить:
powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File .\Start-ActSigner.ps1 -NoUpdate
Или разово предыдущую проверенную версию без сетевой проверки:
powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File .\Start-ActSigner.ps1 -Previous
Если сохранённой предыдущей версии нет, будет открыта исходная копия.

ПОЧЕМУ АКТ С ПОДПИСЬЮ ОТМЕЧЕН ГАЛОЧКОЙ

Проверить подписи (N) означает найденные, но ещё не проверенные файлы.
Галочка включает акт в проверку. После Проверить и подписать КриптоПро
проверит PDF и выбранный сертификат; подтверждённый повтор будет пропущен
без создания новой подписи. Совпадение названий PDF и SIG не требуется.
Существующий целевой SIG можно отметить для проверки. Его наличие само
по себе не подтверждает подлинность, и файл никогда не перезаписывается.
