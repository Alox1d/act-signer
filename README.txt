ПОДПИСЬ АКТОВ ЧЕРЕЗ КРИПТОПРО
Версия 1.1

Запуск: распакуйте весь архив в папку Windows и откройте Start.cmd.
Не запускайте программу прямо из окна ZIP-архива.

ЧТО ИЗМЕНИЛОСЬ В 1.1

- Изменён способ обращения к компонентам КриптоПро: вызовы COM выполняются
  через отражение .NET. Изменение направлено на ошибку чтения 0x80004003.
- Ошибки чтения показываются в окне вместе с этапом и кодом ошибки.
- Запоминаются последняя папка с актами, отдельная папка результата и режим.
- На первом запуске подпись сохраняется рядом с каждым найденным актом.

ЧТО НУЖНО В WINDOWS ВНУТРИ VM

1. Работающий КриптоПро CSP с действующей лицензией, если она нужна
   для вашего сертификата/варианта установки.
2. КриптоПро ЭЦП Browser plug-in (его локальный компонент CAdESCOM).
   Если его ещё нет, программа покажет сообщение. Официальная страница:
   https://cryptopro.ru/products/cades/plugin
   На ней есть отдельный установщик плагина. Браузер для подписи не нужен.
3. Подключённая флешка с ключевым контейнером либо USB-токен и его драйвер.
4. Действующий сертификат ГОСТ Р 34.10-2012 и доступ к его закрытому ключу.
5. Встроенный Windows PowerShell 5.1 и обычный рабочий стол Windows.
   Python, PowerShell 7 и права администратора для запуска скрипта не нужны.

ФЛЕШКА И ВИРТУАЛЬНАЯ МАШИНА

Передайте USB-устройство гостевой Windows через настройки/меню USB вашей VM.
КриптоПро именно внутри VM должен видеть ключевой контейнер. Общая папка
с актами и подключение носителя с ключом являются отдельными настройками.

Программа ищет сертификаты в личном хранилище текущего пользователя Windows
и непосредственно в контейнерах, доступных КриптоПро. Для обновления списка
после подключения носителя нажмите "Обновить". Сертификаты с одинаковым
отпечатком показываются один раз; предпочтение получает доступный контейнер.

Если сертификат один, он будет выбран и показан в окне. Если их несколько,
нужно выбрать нужный. Проверьте владельца, срок действия и отпечаток.
Ключ используется на его носителе; программа не экспортирует закрытый ключ.
PIN вводится в штатном окне КриптоПро/токена, в программе и журнале не хранится.
Количество запросов PIN зависит от токена и настроек КриптоПро. Иногда
достаточно одного ввода, иногда запрос появляется для каждого файла.

Если список пуст:
- прочитайте подробности в поле сертификата: там указан этап и код ошибки;
- убедитесь, что носитель подключён к гостевой Windows и виден в КриптоПро;
- проверьте драйвер токена и срок действия сертификата;
- если в контейнере нет сертификата, установите личный сертификат со связью
  с этим контейнером через инструменты КриптоПро, затем обновите список.
Один файл .cer без доступа к закрытому ключу не позволяет подписывать.
Наличие сертификата в списке ещё не проверяет PIN: доступ к ключу будет
окончательно проверен КриптоПро при подписании.

КАК ПОДПИСАТЬ

1. Распакуйте архив и запустите Start.cmd в Windows внутри VM.
2. Выберите папку с актами. Вложенные папки будут просмотрены автоматически.
   При следующем запуске последняя выбранная папка восстановится.
3. На первом запуске включено "Сохранять рядом с исходниками". Подпись
   каждого акта попадёт в его собственную подпапку рядом с PDF.
   Чтобы использовать отдельную папку результата, снимите флажок и выберите
   папку. Структура вложенных папок сохранится. Выбранный режим запоминается.
4. Подключите носитель, нажмите "Обновить" и выберите свой сертификат.
5. Нажмите "Найти акты". Проверьте список и снимите отметки с ненужных файлов.
6. Нажмите "Подписать". После этого откроется работа в консоли, а КриптоПро
   при необходимости запросит PIN. Дождитесь итоговых чисел и пути к журналу.

КАКИЕ ФАЙЛЫ ПОПАДАЮТ В СПИСОК

Эта версия настроена под исходные файлы актов со следующими названиями:
- Акт_оказанных_услуг.pdf
- Акт_выполненных_работ.pdf
- те же имена с пробелами вместо подчёркиваний;
- копии с числом в скобках, например Акт_оказанных_услуг(1).pdf
  или Акт оказанных услуг (2).pdf.

Регистр букв не важен. Печатные формы не подписываются. Другие имена PDF
в список не попадут. Если акты у вас названы иначе, требуется изменить
правило отбора в ActSigner.Core.psm1; сам подписанный PDF менять не нужно.
Лимит каждого документа и сопутствующего файла: 64 МиБ.
Символические ссылки, junction и другие точки повторной обработки пропускаются.
Для исходной/выходной папки и их родителей такие ссылки не поддерживаются.
Если выбрана выходная папка внутри исходной, она исключается из поиска.

ЧТО ПОЛУЧИТСЯ

Для Акт_оказанных_услуг.pdf создаётся Акт_оказанных_услуг.my.sig.
Это отдельная бинарная подпись CAdES-BES (CMS/PKCS#7, DER), отсоединённая
от документа. Для проверки нужны и PDF, и соответствующий .my.sig.
Сертификат подписанта включается в новую подпись.

При выборе отдельной папки результата туда копируются:
- выбранный исходный акт без изменения его байтов;
- имеющиеся рядом signature*.sig;
- подпись с именем исходного PDF + .sig либо его именем без .pdf + .sig;
- Печатная_форма*.pdf;
- новая собственная подпись *.my.sig.

Не все произвольные файлы из исходных папок копируются. Например, квитанции,
XML и вложения с другими именами нужно хранить вместе с исходным комплектом.
Подписи контрагента сохраняются как есть. Их криптографическая и историческая
проверка в эту программу не входит. Подписывается сам исходный PDF, а не
файл чужой подписи и не печатная форма.

При сохранении рядом копии не создаются: добавляются .my.sig и папка журнала.

НАСТРОЙКИ

Папки и выбранный режим сохраняются для текущего пользователя Windows:
%LOCALAPPDATA%\ActSigner\settings.json
Настройки сохраняются также при закрытии окна без подписания.
В этом файле нет PIN, закрытых ключей или выбранного сертификата.

ПРОВЕРКА, ПОВТОРНЫЙ ЗАПУСК И ОШИБКИ

Каждая новая подпись проверяется КриптоПро относительно точных байтов PDF.
Дополнительно проверяется, что подпись создана выбранным сертификатом,
а исходный файл не изменился во время операции. Только после этого новый
.my.sig сохраняется под окончательным именем. Исходные файлы не редактируются.

КриптоПро проверяет цепочку сертификата и допустимый срок использования
ключа; эти проверки программой не отключаются. Если нужных сертификатов
или списков отзыва нет в кэше, Windows/КриптоПро могут обращаться к УЦ
по сети. Содержимое актов скрипт на сайты и серверы не отправляет.

Существующие .my.sig не перезаписываются. В окне они отмечены как готовые
файлы без возможности повторного выбора. Сам факт наличия такого файла
не означает успешную проверку его содержимого этой программой.

Если исходник изменился и в папке результата есть отличающаяся копия,
программа остановится, сохранив существующий файл. Выберите другую папку
результата для новой редакции. Не меняйте PDF, для которого храните подписи.

При первой ошибке или отмене запроса PIN пакет останавливается. Уже созданные
подписи остаются. Отмена не запускает повторные попытки ввода PIN. После
устранения причины можно повторно запустить программу. При закрытии консоли
или Ctrl+C журнал может быть неполным; законченные подписи сохраняются.

Журнал CSV расположен в папке результата, подпапка _ActSigner_logs.
В нём есть путь, SHA-256 исходного PDF, отпечаток выбранного сертификата,
время, статус и текст ошибки. При пропуске/необработанном файле хеш пустой.
Статусы:
  signed_verified   новая подпись создана и проверена;
  exists_unverified существующий результат пропущен без проверки;
  error             ошибка, пакет остановлен;
  not_processed     до этого файла выполнение не дошло.
Журнал не является доверенной меткой времени или заключением ФНС.

На Windows PowerShell 5.1 очень длинные пути могут не поддерживаться.
При соответствующей ошибке выберите более короткий путь к папке в VM.
Если Windows блокирует запуск правилами организации, используйте разрешённый
в вашей организации способ запуска. Start.cmd задаёт ExecutionPolicy только
для своего процесса PowerShell и не меняет постоянные настройки Windows.

ДАТА И ФОРМАТ ПОДПИСИ

Новая подпись создаётся сейчас, с текущим временем Windows. Сервер доверенных
меток времени (TSA) в этой версии не используется. Атрибут SigningTime не
является независимым подтверждением времени. Программа не исправляет
проблемы исторической проверки чужой подписи и не меняет статус приёмки
акта на портале. Если по договору требуется действие в портале, его нужно
выполнить отдельно. Для долгосрочного архива нужны соответствующий формат
подписи и данные проверки; эта версия решает задачу локальной пакетной подписи.

СОСТАВ И ПРОВЕРКА ПРОГРАММЫ

Start.cmd                   запуск Windows PowerShell 5.1;
Sign-Acts.ps1               запуск окна и пакетной обработки;
ActSigner.UI.psm1           выбор папок, актов и сертификата;
ActSigner.CryptoPro.psm1    локальная подпись и проверка через CAdESCOM;
ActSigner.Settings.psm1     запоминание папок и режима сохранения;
ActSigner.Core.psm1         обработка файлов, копирование и журнал;
README.txt                 эта инструкция.

Исходный код включён полностью. При подготовке проверены синтаксис
PowerShell и файловая логика с тестовой заменой криптографического модуля:
рекурсия, кириллица, скобки/пробелы, исключения, отсутствие перезаписи,
ошибки подписи/проверки и остановка пакета. Среда подготовки Linux,
поэтому реального запуска окна Windows и подписи вашим токеном здесь не было.
В 1.1 дополнительно проверены сохранение настроек и вызовы отражения .NET
на тестовых объектах, включая индексируемые свойства и коллекции.
Работу нового способа вызовов с установленным КриптоПро нужно проверить
в вашей Windows VM; при ошибке её этап и код будут видны прямо в окне.
