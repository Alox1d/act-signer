# Подпись актов через КриптоПро

**Версия 1.1.** Утилита для пакетного подписания PDF-актов в Windows, в том числе внутри виртуальной машины. Для каждого выбранного акта создаёт отдельную подпись `.my.sig` и проверяет её через КриптоПро перед сохранением. Исходные PDF не изменяет, существующие подписи не перезаписывает.

## Известная проблема

При проверке версии 1.1 в Windows VM получена ошибка `0x80004003` на этапе `CAdESCOM.Store.Open` для личного и контейнерного хранилищ. Причина пока не установлена. Замена обычных COM-вызовов PowerShell на отражение .NET эту ошибку в проверенной конфигурации не устранила.

Для разбора добавлен самостоятельный пакет [diagnostics](diagnostics/README.txt). Запустите `diagnostics\Check-CryptoPro.cmd` в той же Windows. Он сравнит открытие хранилищ через PowerShell и CScript в доступных разрядностях и создаст `ActSigner-diagnostics.txt` рядом со скриптами. Отчёт содержит версии, этапы, коды ошибок и количество сертификатов; операции подписи и экспорта ключей в проверке не выполняются. Сам отчёт исключён из Git через `.gitignore`.

## Требования

- Windows с обычным рабочим столом и встроенным **Windows PowerShell 5.1**.
- Работающий **КриптоПро CSP** с действующей лицензией, если она требуется для вашего сертификата и варианта установки.
- [КриптоПро ЭЦП Browser plug-in](https://cryptopro.ru/products/cades/plugin), предоставляющий локальный компонент **CAdESCOM**. Браузер для работы утилиты не нужен.
- Действующий сертификат **ГОСТ Р 34.10-2012** и доступ к его закрытому ключу.
- Флешка с ключевым контейнером или USB-токен с установленным драйвером. В виртуальной машине носитель должен быть доступен именно гостевой Windows и КриптоПро внутри неё.

Python, PowerShell 7 и права администратора для запуска программы не нужны.

## Запуск

1. Скачайте все файлы проекта в одну папку. Если скачан ZIP, сначала распакуйте его целиком.
2. Откройте **`Start.cmd`** в Windows.
3. Выберите папку с актами. Поиск включает вложенные папки.
4. Проверьте режим сохранения. При первом запуске включено **Сохранять рядом с исходниками**: каждая подпись попадёт в ту же подпапку, где найден соответствующий PDF. Чтобы складывать результат отдельно, снимите флажок и выберите папку результата.
5. Выберите свой сертификат. Для повторного поиска сертификатов нажмите **Обновить**. При ошибке этап и код показаны в поле диагностики.
6. Нажмите **Найти акты**, проверьте список и отметьте нужные файлы.
7. Нажмите **Подписать**. Обработка продолжится в консоли; PIN вводится только в штатном окне КриптоПро или токена. Дождитесь результата и пути к журналу.

Не запускайте `Start.cmd` прямо из окна ZIP-архива. Если запуск ограничен политиками организации, используйте разрешённый в ней способ запуска.

## Файлы и сохранение настроек

Поиск рассчитан на `Акт_оказанных_услуг.pdf` и `Акт_выполненных_работ.pdf`. Поддерживаются пробелы вместо подчёркиваний и копии с номером в скобках, например `Акт оказанных услуг (2).pdf`. Регистр не важен. Печатные формы и PDF с другими именами не подписываются. Лимит одного документа или сопутствующего файла: **64 МиБ**.

Для `Акт_оказанных_услуг.pdf` создаётся `Акт_оказанных_услуг.my.sig`. При сохранении в отдельную папку сохраняется структура подпапок; туда также копируются исходные PDF и предусмотренные программой сопутствующие файлы. Их точный перечень есть в [README.txt](README.txt).

Последняя папка с актами, отдельная папка результата и выбранный режим запоминаются, в том числе при закрытии окна без подписания. Настройки текущего пользователя хранятся в `%LOCALAPPDATA%\ActSigner\settings.json`. PIN, ключи и выбранный сертификат в этот файл не записываются.

CSV-журнал находится в `_ActSigner_logs` внутри папки результата. При первой ошибке или отмене PIN пакет останавливается; уже созданные подписи остаются. Повторный запуск пропускает существующие `.my.sig` без их перезаписи и без повторной проверки.

## Тесты

Три тестовых скрипта не требуют доступа к реальному ключу:

```powershell
powershell.exe -NoProfile -File .\ActSigner.Core.Tests.ps1
powershell.exe -NoProfile -File .\ActSigner.CryptoPro.Tests.ps1
powershell.exe -NoProfile -File .\ActSigner.Settings.Tests.ps1
```

| Скрипт | Что проверяет |
| --- | --- |
| `ActSigner.Core.Tests.ps1` | Поиск во вложенных папках, имена файлов, копирование, отсутствие перезаписи, остановку при ошибках и журнал. Криптографические операции заменены тестовыми. |
| `ActSigner.CryptoPro.Tests.ps1` | Вызовы отражения .NET, аргументы, коллекции и сообщения об ошибках на управляемых тестовых объектах. |
| `ActSigner.Settings.Tests.ps1` | Сохранение и восстановление папок и режима, повторную атомарную запись, повреждённые настройки и ошибки записи. |

При подготовке версии 1.1 эти тесты прошли в Linux под PowerShell 7.6.6. В этой среде реальный COM-компонент CAdESCOM, окно Windows и подписание физическим носителем недоступны. Результат последующей проверки открытия хранилищ в Windows описан в разделе об известной проблеме выше; успешная интеграционная проверка подписания ещё предстоит.

## Формат подписи

Результат представляет собой отсоединённую бинарную подпись **CAdES-BES (CMS/PKCS#7, DER)**. Для проверки нужны исходный PDF и его `.my.sig`. Сервер доверенных меток времени в этой версии не используется; чужие подписи и историю приёмки акта программа не проверяет.

Подробная инструкция, ограничения, описание журналов и ссылки на используемые API находятся в [README.txt](README.txt).
