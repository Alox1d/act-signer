# ActSigner: КриптоПро и пакетное подписание PDF-актов

**ActSigner** - утилита на Windows PowerShell для локального пакетного подписания актов оказанных услуг и выполненных работ через **КриптоПро CSP и CAdESCOM**. В окне выбираются папки, сертификат ГОСТ Р 34.10-2012 и документы. Для каждого выбранного PDF предусмотрен отдельный файл электронной подписи **`.my.sig`** в формате **CAdES-BES**.

Исходные PDF сохраняют свои байты. Программа рассчитана на отсоединённую подпись: документ и подпись хранятся отдельными файлами. Есть рекурсивный поиск актов по именам, сохранение рядом с исходниками или в отдельную папку, запоминание папок и CSV-журнал.

<a id="status"></a>

## Статус и известная проблема

> **Версия 1.2: проверка интеграции с КриптоПро не завершена.** Предыдущая версия 1.1 получала `0x80004003` / `NullReferenceException` на этапе `CAdESCOM.Store.Open` в тестовой конфигурации Windows. Независимая диагностика показала отказ прямых вызовов из PowerShell и успешное открытие тех же видов хранилищ через CScript/JScript. Причина `E_POINTER` внутри пути вызова PowerShell пока не установлена.

В версии 1.2 криптографические операции перенесены в локальный процесс **CScript/JScript**, а интерфейс и файловая обработка остаются в PowerShell. **В целевой Windows пока подтверждён только отдельный диагностический `Store.Open` из CScript. Реальные `SignCades` и `VerifyCades` версии 1.2 ещё предстоит проверить пользователю.** Успешное чтение хранилищ не подтверждает полный цикл подписи, работу конкретного токена или полную совместимость с Windows. Для разбора ошибок в репозиторий включён [пакет диагностики](diagnostics/README.txt).

Перед применением к рабочим документам необходимо подтвердить полный цикл на несекретном тестовом PDF в своей конфигурации Windows и КриптоПро, включая проверку результата принимающей стороной.

## Запуск и выбор документов

1. Откройте `Start.cmd` из распакованной папки.
2. Укажите **Папку с актами**. Поиск включает доступные вложенные папки.
3. Проверьте **Сохранять рядом с исходниками**. На первом запуске флажок включён: подпись каждого акта попадёт в его собственную подпапку. Для отдельного комплекта снимите флажок и укажите **Папку результата**.
4. Проверьте сертификат. Если подходящий сертификат один, он выбирается автоматически; если несколько, выберите нужный. В поле сведений показаны владелец, издатель, отпечаток, сроки и источник. Кнопка **Обновить** повторяет поиск сертификатов.
5. Нажмите **Найти акты**. Подходящие файлы без готовой целевой `.my.sig` отмечаются автоматически. Снимите отметки с документов, которые не нужно подписывать. Файлы с существующей подписью недоступны для повторного выбора.
6. Нажмите **Подписать**. Окно выбора закрывается, обработка и её результат выводятся в консоль. Если криптопровайдер запросит PIN, вводите его в штатном окне КриптоПро или токена.
7. Дождитесь итоговых чисел и пути к журналу. Консоль остаётся открытой до нажатия клавиши.

Изменение папки или режима сохранения сбрасывает найденный список: нажмите **Найти акты** ещё раз. Закрытие окна выбора без нажатия **Подписать** не запускает подписание; выбранные папки и режим при этом запоминаются.

## Точные правила отбора актов

Поиск определяется **именем файла**, а не содержимым документа, номером договора, контрагентом или датой. В [Get-ActPlan](ActSigner.Core.psm1) используется шаблон без учёта регистра:

```regex
^Акт[_ ](?:оказанных[_ ]услуг|выполненных[_ ]работ)(?:\s*\(\d+\))?\.pdf$
```

Между основными словами допускается ровно один пробел или одно подчёркивание; их можно смешивать. Перед `.pdf` допускается номер в круглых скобках, с пробельными символами перед ним или без них.

| Имя | Попадёт в список |
| --- | --- |
| `Акт_оказанных_услуг.pdf` | Да |
| `Акт выполненных работ.pdf` | Да |
| `Акт_оказанных услуг(12).PDF` | Да |
| `Акт оказанных услуг (2).pdf` | Да |
| `Акт__оказанных_услуг.pdf` | Нет: два разделителя между словами |
| `Акт_оказанных_услуг_2.pdf` | Нет: номер должен быть в скобках |
| `Акт_оказанных_услуг_2026-01.pdf` | Нет: дополнительный суффикс |
| `Печатная_форма.pdf`, `Счёт.pdf`, `Документ.pdf` | Нет |

Печатная форма может копироваться вместе с актом, но не подписывается вместо него. Для других имён нужно изменить отбор в `ActSigner.Core.psm1` и проверить его на тестовых файлах; настройки пользовательского шаблона в окне нет.

Обход рекурсивный, список сортируется по относительному пути. Скрытые и системные элементы сами по себе не исключаются. Если отдельная папка результата находится внутри исходной, её поддерево не просматривается повторно.

Найденные внутри дерева файлы и каталоги с атрибутом `ReparsePoint`, включая символические ссылки и junction, пропускаются. Ссылка в самой выбранной исходной или выходной папке либо среди их существующих родителей вызывает ошибку. Недоступная папка может прервать поиск целиком: неполный список не следует считать полным комплектом актов.

**Лимит - 64 МиБ (67 108 864 байта) на каждый акт, каждый копируемый сопутствующий файл и новую подпись.** Размер проверяется при обработке. Файлы читаются в память, поэтому реальный расход памяти может превышать этот лимит. Для исходного акта проверяется начало `%PDF-`; полноценного анализа структуры, страниц или содержимого PDF в программе нет.

## Результат и размещение файлов

Для `Акт_оказанных_услуг.pdf` целевой файл называется **`Акт_оказанных_услуг.my.sig`**. Расширение `.pdf` заменяется на `.my.sig`, а не дополняется им.

| Режим | Исходный акт | Новая подпись |
| --- | --- | --- |
| Рядом с исходниками | `C:\Акты\Договор_001\Акт_оказанных_услуг.pdf` | `C:\Акты\Договор_001\Акт_оказанных_услуг.my.sig` |
| Отдельная папка `C:\Результат` | Тот же акт относительно корня `C:\Акты` | `C:\Результат\Договор_001\Акт_оказанных_услуг.my.sig` |

В режиме рядом копии документов не создаются: добавляются новые подписи в папки соответствующих актов и журнал в корне выбранной папки с актами. В отдельной папке сохраняется структура подпапок, копируется выбранный PDF без изменения байтов и создаётся его подпись. Если отдельная папка ещё не выбиралась, интерфейс предлагает `Подписанные_акты` внутри системной папки документов текущего пользователя (`MyDocuments`). Впоследствии восстанавливается сохранённая отдельная папка. Этот путь предлагается при отключении режима рядом с исходниками.

### Какие сопутствующие файлы копируются

В отдельный комплект также входят файлы из **той же папки, где лежит выбранный акт**, если имя соответствует одному из правил без учёта регистра:

| Правило | Пример |
| --- | --- |
| `signature*.sig` | `signature.sig`, `signature(1).sig` |
| Полное имя исходного PDF плюс `.sig` | `Акт_оказанных_услуг.pdf.sig` |
| Имя исходного акта без `.pdf` плюс `.sig` | `Акт_оказанных_услуг.sig` |
| `Печатная_форма*.pdf` | `Печатная_форма_001.pdf` |

Существующие `*.my.sig` и элементы `ReparsePoint` исключаются из этого набора. Пробел вместо подчёркивания в `Печатная_форма` этим правилом не предусмотрен. Квитанции, XML, ZIP и произвольные вложения с другими именами автоматически не копируются.

Связь сопутствующего файла с актом определяется только именем и расположением. При нескольких актах в одной папке шаблоны `signature*` и `Печатная_форма*` могут дать общий набор файлов. Программа не проверяет чужие подписи и не устанавливает, к какому документу они относятся. Оригинальный комплект документов следует сохранять отдельно от производного результата.

### Формат подписи

Код использует `SignCades` с типом **CAdES-BES** и признаком отсоединённой подписи. Возвращённая КриптоПро строка Base64 декодируется в бинарный файл `.my.sig`; это подпись семейства CMS/PKCS#7. В подпись включается открытый сертификат подписанта. Криптографический интерфейс приложения: [ActSigner.CryptoPro.psm1](ActSigner.CryptoPro.psm1), вызовы CAdESCOM: [ActSigner.CryptoPro.js](ActSigner.CryptoPro.js). Принцип отсоединённой подписи: [официальный пример КриптоПро](https://docs.cryptopro.ru/cades/plugin/plugin-samples/plugin-samples-sign-detached).

Для проверки нужны **точные исходные байты PDF и соответствующий файл подписи**. Встроенная подпись PDF/PAdES, визуальный штамп и объединённый PDF не создаются. Расширение `.my.sig` - соглашение этой утилиты; требования принимающей системы к именам и формату нужно проверить отдельно.

## Сертификат и порядок подписания

### Как формируется список сертификатов

Программа рассматривает контейнерное хранилище КриптоПро (`100`) и личное хранилище текущего пользователя Windows `CurrentUser\My` (`2`). Фильтр оставляет сертификаты, для которых:

- `HasPrivateKey` сообщает о связи с закрытым ключом;
- алгоритм открытого ключа имеет OID `1.2.643.7.1.1.1.1` или `1.2.643.7.1.1.1.2`;
- срок действия уже начался и ещё не закончился по текущему времени Windows.

Одинаковые отпечатки объединяются. Ошибки чтения, неподходящие алгоритмы, отсутствие связи с ключом и сроки выводятся в поле сведений о сертификате. Пустой список сам по себе не доказывает, что USB-носитель не подключён.

Выбор сертификата не хранится между запусками. При обновлении в том же окне предыдущий выбор сохраняется, если найдено единственное точное совпадение. Наличие сертификата в списке не проверяет правильность PIN и не гарантирует доступность ключа в момент подписания.

Один файл `.cer` без доступного закрытого ключа не позволяет подписать документ. PIN программа не принимает отдельным полем и не передаёт в командной строке. Число запросов PIN и кэширование авторизации определяются КриптоПро и носителем; один ввод на весь пакет не гарантируется.

### Как взаимодействуют PowerShell и CScript в версии 1.2

[ActSigner.CryptoPro.psm1](ActSigner.CryptoPro.psm1) запускает локальный процесс `cscript.exe` со сценарием [ActSigner.CryptoPro.js](ActSigner.CryptoPro.js). PowerShell отвечает за интерфейс, пути, чтение точных байтов PDF, проверку ответов и сохранение результатов. Сценарий JScript получает содержимое PDF через потоки, не принимает пути к документам и сам не читает или записывает файлы. CAdESCOM вызывается внутри дочернего процесса; закрытый ключ и PIN в протокол между процессами не передаются.

Обмен идёт через перенаправленные стандартные потоки ввода и вывода, без сетевого сервера. Используется версионированный построчный протокол `ACTSIGNER/1`: символы протокола ASCII передаются в UTF-16LE без BOM, двоичные данные кодируются Base64 порциями до 49 152 символов. Это кодирование, а не шифрование. Документы и подписи находятся в памяти локальных процессов, поэтому требования к защите Windows сохраняются.

На пакет создаётся один подписывающий процесс, который сохраняет сеанс выбранного сертификата. Это позволяет не сбрасывать процессное состояние CSP между актами, но не обещает единственного запроса PIN. Для каждой проверки новой подписи запускается отдельный процесс. Ошибка или таймаут останавливает обработку без автоматической повторной подписи.

| Операция | Лимит ожидания |
| --- | --- |
| Подготовка компонентов (`CHECK`), поиск сертификатов (`DISCOVER`), выбор сертификата (`SELECT`) | 60 секунд на запрос |
| Создание подписи (`SIGN`) | 10 минут, включая ожидание PIN и проверки КриптоПро |
| Проверка новой подписи (`VERIFY`) | 10 минут |
| Штатное закрытие процесса (`CLOSE`) | 5 секунд, затем ограниченное завершение процесса |

На Windows x64 выбирается системный 64-разрядный CScript; при вызове из 32-разрядного процесса используется путь `Sysnative`. Автоматического переключения на x86 после ошибки нет. Это отличается от отдельной диагностической программы, которая намеренно сравнивает обе доступные разрядности.

### Что происходит с каждым выбранным актом

Обработка идёт последовательно. [Invoke-ActBatch](ActSigner.Core.psm1) выполняет следующие шаги:

1. Проверяет целевой путь; при уже существующей `.my.sig` пропускает акт без проверки её содержимого.
2. Читает акт и нужные сопутствующие файлы, проверяет размеры, возможность записи и конфликты существующих копий.
3. Передаёт исходные байты криптографическому модулю для создания подписи.
4. Проверяет новую подпись относительно тех же байтов и проверяет, что подписант соответствует выбранному сертификату.
5. Повторно проверяет SHA-256 исходного PDF; при отдельной папке сохраняет копии и проверяет их хеши.
6. Ещё раз проверяет исходный PDF и сохраняет новую подпись через временный файл в той же папке без перезаписи существующего результата.
7. Записывает итоговую строку журнала.

Криптографическая проверка выполняется в памяти до сохранения результата. Отдельного повторного вызова проверки для уже записанного `.my.sig` нет. SHA-256 в файловой логике нужен для контроля неизменности байтов и журнала; это не переключатель алгоритма электронной подписи ГОСТ.

В криптографическом модуле предусмотрен `CheckCertificate = true`. По [описанию КриптоПро](https://docs.cryptopro.ru/cades/reference/cadescom/cadescom_interface/icpsigner6checkcertificate), эта настройка включает проверку цепочки перед подписью, в том числе сроков использования закрытого ключа. Проверка не отключается ради продолжения пакета.

<a id="settings-and-logs"></a>

## Настройки, журнал и повторный запуск

### Запоминание папок

Настройки текущего пользователя сохраняются в:

```text
%LOCALAPPDATA%\ActSigner\settings.json
```

В JSON только три поля: `SourceRoot`, `SeparateOutputRoot`, `SaveBesideSources`. Запоминаются последняя папка с актами, последняя отдельная папка результата и выбранный режим. На первом запуске режим рядом включён; явно выбранный режим отдельной папки сохраняется при следующих запусках. Закрытие окна без подписания тоже сохраняет настройки.

Временно недоступный сетевой или съёмный путь не стирается. Отсутствующий или повреждённый файл настроек приводит к значениям по умолчанию. Запись выполняется через временный файл и замену в том же каталоге. Ошибка сохранения не блокирует подписание, но выбор может не восстановиться в следующий раз. Реализация: [ActSigner.Settings.psm1](ActSigner.Settings.psm1).

Это обычный текстовый JSON с путями, без шифрования. В нём нет PIN, ключей, сертификатов и сохранённого выбора подписанта. Для сброса предпочтений можно при закрытой программе переименовать `settings.json`, сохранив его при необходимости.

### CSV-журнал

При запуске пакетной обработки создаётся файл в **`<папка результата>\_ActSigner_logs`**. Для режима рядом папка результата совпадает с выбранным корнем актов. Имя журнала имеет вид `act-sign-yyyyMMdd-HHmmss-fff-xxxxxxxx.csv`.

| Поле | Содержимое |
| --- | --- |
| `Source` | Полный путь исходного PDF |
| `Destination` | Полный путь целевой `.my.sig` |
| `Hash` | SHA-256 прочитанного исходного PDF |
| `Thumb` | Отпечаток сертификата, выбранного для текущего запуска |
| `Status` | Статус обработки |
| `Message` | Пояснение или текст ошибки с этапом |
| `Time` | Время Windows в ISO 8601 с локальным смещением |

Журнал использует запятую как разделитель, UTF-8 с BOM и CRLF. Поля заключаются в кавычки, формулоподобное начало ячейки экранируется. Строки сбрасываются на диск по мере обработки.

| Статус | Значение |
| --- | --- |
| `signed_verified` | Новая подпись создана, проверена в памяти и сохранена |
| `exists_unverified` | Целевой файл уже существует и пропущен без проверки |
| `error` | Обработка этого акта завершилась ошибкой; пакет остановлен |
| `not_processed` | До акта не дошло выполнение после остановки |

У пропущенных и необработанных актов `Hash` пустой. При ошибке хеш есть только если исходник уже удалось прочитать. Поле `Thumb` у `exists_unverified` **не устанавливает автора существующей подписи**: это по-прежнему выбор текущего запуска.

Окно исключает уже готовые файлы из выбранного плана ещё до пакетной обработки. Поэтому CSV не является описью всех обнаруженных файлов. Статус `exists_unverified` возникает, если существующий результат дошёл до обработчика, например появился после поиска. Ошибка открытия сертификата до запуска пакета может не создать CSV вообще; для неё используйте диагностику и обезличенный текст ошибки.

### Остановка и конфликты

**Первая ошибка обработки, включая отмену PIN, останавливает оставшийся пакет.** Автоматических повторов ввода PIN нет. Уже сохранённые подписи остаются, а оставшиеся выбранные акты получают `not_processed`. При принудительном закрытии консоли или `Ctrl+C` журнал может оказаться неполным.

Существующие `.my.sig` не перезаписываются и не проверяются повторно. Само наличие файла не подтверждает валидность подписи, неизменность PDF или полноту отдельного комплекта. Такой пропуск не восстанавливает отсутствующие копии и сопутствующие файлы.

Существующая копия PDF или сопутствующего файла с тем же SHA-256 используется без перезаписи. Если байты отличаются, обработка останавливается; выберите новую папку результата для другой редакции документа. Не заменяйте PDF, для которого уже храните подписи.

Общей транзакции для папки или пакета нет. При ошибке после записи части копий они и созданные каталоги могут остаться. Контроль хешей и запись через временный файл уменьшают риск незаметного изменения, но не заменяют резервные копии и проверку полного комплекта.

<a id="diagnostics"></a>

## Диагностика CAdESCOM и разрядности

При `Store.Open 0x80004003`, пустом списке сертификатов или различиях между окружениями запустите:

```text
diagnostics\Check-CryptoPro.cmd
```

Запускать нужно в той же Windows и под тем же пользователем, где возникает ошибка. Папка `diagnostics` должна быть доступна для записи. Результат - **`diagnostics\ActSigner-diagnostics.txt`**. Повторный запуск перезаписывает предыдущий отчёт. Полная инструкция: [diagnostics/README.txt](diagnostics/README.txt).

Пакет собирает версии Windows, PowerShell и CLR, разрядность процесса, регистрацию `CAdESCOM.Store`, имя DLL и её числовые версии. Дополнительно читает количество сертификатов `.NET CurrentUser/My` с `ReadOnly | OpenExistingOnly` и сравнивает следующие COM-вызовы:

| ID проверки | Вызов |
| --- | --- |
| `CurrentUserReadOnly` | `Open(2, 'My', 0)` |
| `DefaultOpen` | `Open()` |
| `CurrentUserLocationOnly` | `Open(2)` |
| `CurrentUserMaximumAllowed` | `Open(2, 'My', 2)` |
| `MemoryReadOnly` | `Open(0, 'My', 0)` |
| `ContainerReadOnly` | `Open(100, 'My', 0)` |

Пробы выполняются через прямые вызовы PowerShell и независимо через CScript/JScript для доступных архитектур. Каждый вариант получает новый объект в отдельном процессе, лимит попытки - 30 секунд. Ошибка или таймаут не отменяет остальные попытки. Если на Windows x64 зависает каждая из 26 внешних попыток, весь запуск может занять около 13 минут.

Диагностика не создаёт подписи и не вызывает добавление/удаление сертификатов или экспорт ключей. Даже в пробе режима `2`, запрашивающего максимальные доступные права открытия, сценарий только читает `Count` и закрывает хранилище. Имена владельцев, отпечатки, содержимое сертификатов и имена контейнеров намеренно не включаются в отчёт. Вместо полных сообщений исключений сохраняются этапы, типы и HRESULT; непредвиденный вывод хостов дополнительно очищается от некоторых путей. Перед публикацией всё равно просмотрите текст целиком.

На обычной Windows x64 [Start.cmd](Start.cmd) выбирает 64-разрядный Windows PowerShell. Диагностика сравнивает его с x86 и CScript. Успех CScript при сбое PowerShell или различие x86/x64 помогает сузить поиск причины, но не устанавливает конкретный дефект. Разные `FileVersion` DLL x86 и x64 также не являются самостоятельным признаком неисправности.

Нет подтверждённого основания исправлять `0x80004003` отключением защит Windows, копированием случайных DLL или перерегистрацией COM по универсальной команде. Сначала нужен отчёт с результатами конкретных попыток.

### Windows в VirtualBox и USB-токен

КриптоПро CSP, CAdESCOM и драйвер используемого токена должны быть доступны **в гостевой Windows**, где запускается программа. Установка только на хосте не предоставляет гостевой системе её собственный COM-компонент.

VirtualBox предоставляет гостю USB-устройство через виртуальный USB-контроллер. Выбор устройства и USB-фильтры описаны в [официальном руководстве Oracle, USB Settings](https://docs.oracle.com/en/virtualization/virtualbox/7.2/user/working-with-vms.html). Подключайте нужный токен к гостю и проверяйте его видимость средствами КриптоПро внутри гостевой Windows; конфигурацию контроллера выбирайте по руководству для своей версии VirtualBox и гостевой ОС.

Общая папка с PDF и доступ к USB-токену - отдельные механизмы. Наличие актов в общей папке не подтверждает доступ к ключу. Общие папки VirtualBox описаны отдельно в [документации Guest Additions](https://docs.oracle.com/en/virtualization/virtualbox/7.2/user/guestadditions.html). Если сохранение рядом недоступно для записи, выберите отдельную доступную папку результата внутри гостевой Windows.

ActSigner не настраивает VirtualBox и не гарантирует совместимость конкретного токена, USB-контроллера или общей файловой системы. Сроки сертификатов проверяются по времени гостевой Windows, поэтому неверная дата также может исключить сертификат из списка.

<a id="security"></a>

## Данные, ключи и ограничения

### Что делает код с ключом и данными

Операции закрытого ключа выполняет КриптоПро. Программа не содержит команд экспорта закрытого ключа и не сохраняет PIN. Чтение открытого X.509-сертификата для фильтрации и отображения метаданных не является экспортом ключевого контейнера. Реальная защита ключа зависит также от носителя, настроек CSP, прав пользователя и состояния Windows.

В коде приложения нет загрузки PDF в веб-сервис, телеметрии или отправки документов на сервер. Полную работу без сети это не гарантирует: проверка сертификатов средствами Windows/КриптоПро может зависеть от доступа к ресурсам удостоверяющего центра. Если исходные или выходные папки синхронизируются облачным клиентом, файлы могут передаваться этим клиентом независимо от ActSigner.

| Артефакт | Что нужно учитывать перед передачей |
| --- | --- |
| Исходный PDF и его копии | Содержимое документа и возможные персональные или коммерческие данные |
| `.my.sig` и чужие `.sig` | Подпись может содержать открытый сертификат и сведения о подписанте; отсутствие закрытого ключа не делает файл анонимным |
| Основной CSV-журнал | Полные пути, отпечаток сертификата, хеш документа, время и текст ошибок |
| `settings.json` | Выбранные пути, которые могут раскрывать имя пользователя, клиента или сетевого ресурса |
| Диагностический TXT | Версии, архитектура, регистрационные сведения и количество сертификатов; автоматическое сокращение путей не заменяет просмотр перед публикацией |

**Не добавляйте в публичный репозиторий или Issue ключевые контейнеры, `.pfx`/`.p12`, PIN, реальные акты, подписи или необезличенные журналы.** Скриншот окна сертификата тоже может содержать ФИО, реквизиты и отпечаток. Для воспроизведения ошибки используйте документ без персональных данных.

### Границы текущей версии

- Поддерживается фиксированный набор имён PDF-актов и сертификаты ГОСТ-2012. Произвольные документы, RSA, ГОСТ-2001, разные подписанты для файлов одного пакета и шаблоны имён в интерфейсе не реализованы.
- Подписание последовательное, без фонового наблюдения за папками, планировщика и параметров командной строки для полностью автоматической обработки.
- PDF не анализируется как бухгалтерский документ и не проверяется на вредоносное содержимое. Контроль `%PDF-` не является полной проверкой формата.
- Отсутствуют проверка чужих и ранее созданных подписей, восстановление исторической валидности и подтверждение полномочий подписанта.
- Добавляется время текущей Windows; сервер доверенных меток времени TSA не используется. Атрибут `SigningTime` и время CSV не являются независимым подтверждением времени.
- CAdES-T, CAdES-X Long Type 1 и архивные форматы подписи в текущем коде не создаются. Полный комплект данных для долгосрочной проверки автоматически не собирается.
- Нет интеграции с порталом ЭДО или изменения статуса приёмки акта. Создание локального файла подписи не выполняет действия в сторонней системе.
- Очень длинные пути и особенности сетевых/виртуальных файловых систем требуют отдельной проверки в целевой Windows. При ошибке длины пути используйте более короткий доступный путь.

## Тесты и разработка

В корне находятся самостоятельные тестовые скрипты. Они создают временные тестовые файлы и не требуют настоящего ключа:

```powershell
powershell.exe -NoProfile -File .\ActSigner.Core.Tests.ps1
powershell.exe -NoProfile -File .\ActSigner.CryptoPro.Tests.ps1
powershell.exe -NoProfile -File .\ActSigner.Settings.Tests.ps1
```

| Скрипт | Проверяемая область |
| --- | --- |
| [ActSigner.Core.Tests.ps1](ActSigner.Core.Tests.ps1) | Рекурсивный отбор и исключение выходной папки, варианты имён, копирование предусмотренных файлов, пропуск существующей подписи, конфликт изменённого исходника со старой копией, остановка при ошибке подписи/проверки, BOM журнала и пример экранирования CSV. Криптография заменена тестовыми функциями. |
| [ActSigner.CryptoPro.Tests.ps1](ActSigner.CryptoPro.Tests.ps1) | Протокол и точность передачи байтов, выбор разрядности и экранирование аргументов, контракт подписи и проверки, совпадение подписанта, обработка ошибок и закрытого сеанса. Встроенный JScript-набор с имитацией COM проверяет отбор сертификатов, повторное подписание в одном процессе, повторную проверку срока, настройки CAdES-BES, неверные ответы и повреждённые данные протокола. |
| [ActSigner.Settings.Tests.ps1](ActSigner.Settings.Tests.ps1) | Первоначальные значения, восстановление папок и обоих режимов, повторная атомарная запись, набор полей, повреждённые данные и ошибки сохранения. |

Криптографический тест состоит из части PowerShell и встроенного набора имитаций JScript. **Node.js нужен только для JScript-части теста, приложению он не требуется.** Тест сам создаёт временный JS-файл и удаляет его при завершении. Без `node` в `PATH` выполняется часть PowerShell, а JScript-часть явно отмечается `SKIP`. Проверка junction/symlink в Core также выполняется только если среда позволяет создать тестовую ссылку; иначе отмечается `SKIP`.

При подготовке версии 1.2 новый `ActSigner.CryptoPro.Tests.ps1` прошёл в Linux под PowerShell 7.6.6: проверки PowerShell и все 21 сценарий JScript с имитацией COM завершились успешно. Дополнительно на временных имитаторах процессов проверены повторный обмен в одном процессе, передача двоичных данных через границы порций с контролем SHA-256, большой поток stderr, таймауты и повреждённые ответы. Эти отдельные имитаторы транспорта не входят в репозиторий. Такие проверки подтверждают локальную логику протокола, но не поведение настоящего Windows Script Host или CAdESCOM.

Тесты не покрывают все ограничения и сбои файловой системы. Наличие проверки размера, блокировок или хешей в коде не означает, что все их граничные и конкурентные сценарии протестированы. Windows Forms, настоящий PIN, драйверы и аппаратные носители этими скриптами не проверяются. Актуальный статус интеграции указан [в начале README](#status).

При подготовке диагностического пакета отдельно проверялись синтаксис, аргументы с кириллицей и `&`, вывод stdout/stderr, кодировка отчёта, таймаут с продолжением и имитации ошибок COM. Эти вспомогательные имитаторы не входят в репозиторий. Отдельно подтверждён диагностический факт: в тестовой Windows CScript открывает хранилища, прямой путь PowerShell возвращает ошибку. Полный пользовательский отчёт в репозитории не публикуется.

<a id="faq"></a>

## Частые вопросы

### Почему нужного PDF нет в списке?

Проверьте [точное имя](#file-selection), выбранный корень и вложенные папки. Дополнительная дата, двойные разделители или другой суффикс не соответствуют шаблону. Элементы `ReparsePoint` пропускаются, отдельная выходная папка внутри исходной исключается. Программа не распознаёт акт по тексту.

### Почему сертификат виден в Windows, но отсутствует в ActSigner?

Важны текущий пользователь, доступная процессу регистрация COM, алгоритм, срок действия и связь с закрытым ключом. Прочитайте сообщения в поле сертификата и запустите [диагностику](#diagnostics). Наличие сертификата в другой программе или хранилище не устанавливает причину сбоя `CAdESCOM.Store.Open`.

### Почему нельзя снова отметить файл с `.my.sig`?

Существующий результат защищён от перезаписи. Проверки его валидности в интерфейсе нет. Для новой редакции документа используйте отдельный комплект и новую папку результата, сохраняя прежний PDF вместе с его прежней подписью.

### Можно ли использовать PowerShell 7 вместо Windows PowerShell 5.1?

Для запуска приложения используйте `Start.cmd`: `Sign-Acts.ps1` требует редакцию `Desktop`. Проход отдельных тестов на PowerShell 7 не означает поддержку этой среды для приложения.

### Будет ли PIN запрошен один раз?

Это зависит от носителя и CSP. В программе нет собственного хранилища PIN и управления кэшем токена. Отмена штатного запроса останавливает пакет; автоматического повторного ввода нет.

### Почему подпись не отображается внутри PDF?

Результат отсоединённый: `.my.sig` лежит отдельно, PDF не редактируется. Проверяющей программе нужно передать оба файла. Поддержку формата и требования к имени уточняйте для конкретной принимающей системы.

### Решает ли программа проблему старой чужой подписи или приёмки на портале?

Нет. Она создаёт новую локальную подпись текущего подписанта, не проверяет чужую историю подписания, не получает доверенную метку времени и не выполняет действия на портале ЭДО.

### Как сообщить об ошибке без персональных данных

Для [Issue в этом репозитории](https://github.com/Alox1d/act-signer/issues) полезны:

1. Версия ActSigner или commit, версия и разрядность Windows, наличие виртуальной машины.
2. Версии CSP и CAdESCOM, если известны; модель носителя без серийного номера, если проблема связана с ним.
3. Шаги, ожидаемый и фактический результат: при запуске, поиске, чтении сертификатов, подписании или сохранении.
4. Точное название этапа и HRESULT, например `Store.Open`, `0x80004003`, `NullReferenceException`.
5. Просмотренный и при необходимости дополнительно обезличенный `ActSigner-diagnostics.txt` для COM-сбоев.
6. Для файловой ошибки - вымышленные имена и структуру папок с теми же особенностями пути, размер тестового файла и режим сохранения.

Не прикладывайте настоящий акт, сертификат, `.my.sig`, полный CSV, снимок окна с реквизитами, ключевой контейнер или PIN. Если ошибка воспроизводится только на реальных документах, сначала опишите условия текстом. Из сообщения и путей удалите ФИО, ИНН, названия клиентов, имена пользователей и сетевых ресурсов.

## English summary

**ActSigner** is a Windows PowerShell 5.1 utility for batch signing Russian PDF service/work completion acts with **CryptoPro CSP**, **CAdESCOM** and GOST R 34.10-2012 certificates. It uses filename-based recursive discovery, a Windows Forms selection dialog, detached **CAdES-BES / CMS** signatures saved as `.my.sig`, optional output copies, remembered folders and CSV logs. Source PDF bytes are preserved. The scripts do not export private keys or store PINs.

Version 1.1 encountered `CAdESCOM.Store.Open` failures (`0x80004003`, `NullReferenceException`) in a test Windows environment, while independent CScript/JScript probes could open the stores. **Version 1.2 uses a local CScript/JScript backend for COM operations; real signing integration still needs validation.** Included tests exercise local helpers and file handling. See the [status](#status) and [diagnostics package](diagnostics/README.txt) before use. Never upload private keys, personal documents or unredacted logs to public issues.
