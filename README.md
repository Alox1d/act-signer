# ActSigner: КриптоПро и пакетное подписание PDF-актов

**ActSigner** - утилита на Windows PowerShell для локального пакетного подписания актов оказанных услуг и выполненных работ через **КриптоПро CSP и CAdESCOM**. В окне выбираются папки, сертификат ГОСТ Р 34.10-2012 и документы. Для каждого выбранного PDF предусмотрен отдельный файл электронной подписи **`signature_<фамилия>.sig`** в формате **CAdES-BES**.

Исходные PDF сохраняют свои байты. Программа рассчитана на отсоединённую подпись: документ и подпись хранятся отдельными файлами. Есть рекурсивный поиск актов по именам, сохранение рядом с исходниками или в отдельную папку, запоминание папок и CSV-журнал.

<a id="status"></a>

## Статус и известная проблема

**Версия 1.5.1 исправляет блокировку из-за истёкшего сертификата соседней подписи.** Состав подписантов CMS, математическая проверка точных байтов PDF и доверие к сертификатам теперь разделены. Чужая подпись с истёкшим сертификатом допускает добавление отдельной подписи, если её состав и математика установлены. Подтверждённая подпись выбранного сертификата пропускается без ключа. Неопределённый результат блокирует этот акт; независимые акты продолжают обрабатываться.

На Windows 11 с Windows PowerShell 5.1, CryptoPro CSP 5.0.13300, CAdESCOM 2.0.15500 и USB-токеном проверены реальное создание ГОСТ-подписи через CScript, полная проверка CAdESCOM и повтор без обращения к ключу. Проверены истёкший сертификат чужого подписанта, изменённый PDF, повреждённый SIG и два реальных ГОСТ-подписанта в обоих порядках. SHA-256 исходного PDF и чужого SIG сохранились. Это проверка одной конфигурации; принимающая сторона может применять собственные требования к комплекту и доверию. Приватные документы и отчёты в репозиторий не включены.

Исторический сбой прямых вызовов `Store.Open` из PowerShell обходится локальным CScript/JScript backend, введённым в 1.2. Для диагностики доступен [отдельный пакет](diagnostics/README.txt).

## Автообновление при запуске

Начиная с версии **1.5.0**, `Start.cmd` открывает установленную программу и отдельно запускает фоновую проверку стабильного релиза в [Alox1d/act-signer](https://github.com/Alox1d/act-signer/releases). Загрузка с GitHub не выполняется в потоке запуска окна и не задерживает начало работы с актами. **Подготовленная новая версия включается при следующем запуске программы.** Текущий пакет подписания продолжает работать на той версии, на которой был открыт.

Для первого перехода с 1.4 или более ранней версии нужно один раз скачать [готовый ZIP последнего релиза](https://github.com/Alox1d/act-signer/releases/latest), полностью распаковать его и запустить новый `Start.cmd`. Старый `Start.cmd` из 1.4 не содержит механизма обновления. Название окна показывает версию реально запущенного приложения.

### Что происходит при обновлении

1. Локальный запускатель проверяет подготовленную версию и выбирает её либо файлы из распакованной папки.
2. Отдельный скрытый процесс читает последний стабильный релиз. Git, вход в GitHub, токен доступа и права администратора не требуются.
3. Более новая версия загружается во временную папку. Проверяются размер и SHA-256 архива, состав файлов, хеш каждого файла, версия и синтаксис PowerShell.
4. После успешной проверки целая папка версии сохраняется отдельно, затем одним атомарным изменением обновляется указатель запуска. Предыдущая версия остаётся на месте.

Используется [GitHub Releases API](https://docs.github.com/en/rest/releases/releases#get-the-latest-release), а не ZIP текущей ветки. Релиз публикуется только после проверок на Windows. Неполный черновик релиза не становится обновлением; установщик также сверяет номер тега, манифест и имя архива.

Если нет интернета, GitHub недоступен, запрос ограничен по времени, архив не прошёл проверку или каталог обновлений недоступен для записи, установленная программа продолжает запускаться. Оборванная загрузка не заменяет рабочую версию. Повреждённая сохранённая версия не запускается: используется проверенная предыдущая или исходная распакованная копия.

Файлы обновлений хранятся в `%LOCALAPPDATA%\ActSigner\updates`. Запомненные папки остаются в `%LOCALAPPDATA%\ActSigner\settings.json`. Установщик не получает пути актов, сведения о сертификате или PIN, не обращается к закрытому ключу и не меняет PDF, подписи либо журналы подписания. Папки версий пока не удаляются автоматически, чтобы не затронуть ещё работающий экземпляр.

**Граница проверки:** хеши подтверждают целостность файлов относительно релиза, полученного по HTTPS из указанного репозитория. Это не отдельная цифровая подпись издателя и не защита от человека, который уже может изменять программы и настройки вашей учётной записи.

### Запуск без проверки обновления и возврат к предыдущей версии

В PowerShell, открытом в распакованной папке программы:

```powershell
# Использовать готовую локальную версию без новой сетевой проверки
powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File .\Start-ActSigner.ps1 -NoUpdate

# Разово запустить предыдущую проверенную версию без сетевой проверки
powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File .\Start-ActSigner.ps1 -Previous
```

`-Previous` действует только на этот запуск. Если предыдущей сохранённой версии нет, открывается версия из исходной папки. Обычный последующий `Start.cmd` снова выберет активную проверенную версию. Запуск `Sign-Acts.ps1` напрямую также обходит запускатель и автообновление, но требует Windows PowerShell 5.1 и STA.

## Имена файлов подписи

По умолчанию новая подпись называется `signature_<фамилия>.sig`, например `signature_ivanov.sig`. Фамилия берётся из атрибута `surname` выбранного сертификата, русские буквы переводятся в латиницу, неподходящие символы заменяются. При отсутствии фамилии используется `signature_cert_<12 символов отпечатка>.sig`. Имя помогает различать файлы; подписант устанавливается по содержимому CMS и сертификату.

В окне рядом с кнопками поиска есть запоминаемый выбор: `signature_<фамилия>.sig`, `<имя акта>_<фамилия>.sig` или прежний `<имя акта>.my.sig`. Старые подписи с любыми поддерживаемыми именами продолжают распознаваться. Перезаписи и автоматического переименования существующих файлов нет. Если несколько выбранных актов в одной папке получили одинаковый целевой путь, они блокируются до обращения к ключу. Храните разные акты в отдельных папках: формат с именем акта различает целевые имена, но подпись первого PDF может заблокировать второй как неопределённая соседняя подпись. Проверка соседей по-прежнему применяется к каждому PDF.

## Проверка соседних подписей в версии 1.5.1

Перед созданием новой подписи программа ищет **`.sig`, `.p7s`, `.p7m` и `.sgn`** с любыми именами рядом с PDF, а в отдельном режиме также рядом с выходным PDF. Список перечитывается при обработке. Статусы **Проверить подписи (N)** и **Проверить .my.sig** в окне обозначают найденные, ещё не проверенные файлы. Существующую `.my.sig` можно отметить для проверки; перезаписи не будет.

| Результат проверки | Действие |
| --- | --- |
| Подпись выбранного сертификата математически подтверждена над точными байтами PDF | `already_signed`, без новой подписи и обращения к ключу |
| Все реальные подписанты установлены, их математические подписи подтверждены, выбранного сертификата среди них нет | Можно добавить отдельную подпись; в консоли и журнале указаны чужие подписи и непроверенное доверие |
| Возможная собственная подпись не подтверждена, состав не установлен, файл повреждён или недоступен | Ошибка этого акта, без новой подписи; независимые акты продолжаются |
| Пользователь отменил криптографическую операцию или общий сеанс подписи неисправен | Пакет останавливается с отдельной причиной; оставшиеся акты получают `not_processed` |

Сравнивается точный отпечаток сертификата, включая любую позицию в контейнере с несколькими `SignerInfo`. Сертификат из встроенной цепочки сам по себе не считается подписантом. Отсутствующие или неоднозначно соответствующие сертификаты не превращаются в отсутствие подписи. Ошибка математической проверки может означать изменение PDF или повреждение SIG; программа оставляет результат неопределённым.

Поддерживаются отсоединённые CMS/PKCS7, включая CAdES, в бинарном DER/BER, Base64 и PEM `CMS`/`PKCS7`. Windows CryptoAPI читает реальные идентификаторы `SignerInfo`, однозначно сопоставляет встроенные сертификаты и вызывает документированную [CryptVerifyDetachedMessageSignature](https://learn.microsoft.com/en-us/windows/win32/api/wincrypt/nf-wincrypt-cryptverifydetachedmessagesignature) для каждого индекса. Закрытый ключ не нужен. **Математический успех не подтверждает доверие, сроки цепочки, отзыв сертификатов или время подписания.** Истёкший чужой сертификат не является обязательным препятствием для отдельной новой подписи. Полная проверка выбранного сертификата и новой подписи через CAdESCOM сохранена.

Файл с вложенным документом, неподдерживаемый формат, лишние байты после CMS или неясная структура требуют ручного разбора. Лимит каждого PDF/SIG - 64 МиБ, число подписантов - 4096; суммарное повторное хеширование PDF ограничено 512 МиБ. Ссылки на файлы не открываются.

Подписывающий сеанс создаётся только перед первой действительно новой подписью. При пропуске существующей собственной подписи новый комплект копий не создаётся. В журнале указан фактически найденный файл. Набор соседних файлов и хеши повторно проверяются перед обращением к ключу и публикацией результата. Одновременное подписание одного комплекта несколькими процессами не поддерживается.

## Исправление паузы консоли в версии 1.4

В обычной консоли Windows включённый QuickEdit позволяет выделять текст мышью. Во время выделения запись в консоль может ждать его отмены, поэтому пакет может остановиться на строке `[1/6]` даже после сохранения первой подписи. Если в заголовке появилось **Выбрать** или **Select**, нажмите **Esc** в этом окне и проверьте, продолжилась ли обработка. Поведение блокировки видно в [исходном коде консоли Microsoft](https://github.com/microsoft/terminal/blob/main/src/host/selection.cpp).

ActSigner 1.4 отключает QuickEdit на время работы и восстанавливает прежний режим выделения при завершении. Изменение действует для текущей консоли; постоянные настройки Windows не меняются. Другие режимы ввода, включая обработку Ctrl+C, сохраняются. Для этого используется [SetConsoleMode](https://learn.microsoft.com/en-us/windows/console/setconsolemode). Вручную включённый режим выделения по-прежнему можно завершить клавишей Esc.

Для установки полностью распакуйте новый ZIP и запустите его `Start.cmd`: в заголовке должно быть **Подписание актов 1.5.1**. Дальнейшие версии подготавливаются автоматически, как описано в разделе [автообновления](#auto-update).

## Интерфейс версии 1.3

В маленьком окне VM прежняя компоновка оставляла таблице актов почти одну строку заголовков. В версии 1.3 список получает всё свободное место по высоте, а настройки занимают компактную верхнюю часть окна.

- Таблица показывает имя файла вместе с подпапкой, отметку выбора и статус. Длинный полный путь доступен при наведении; список прокручивается внутри таблицы.
- Полные данные сертификата и ошибки открываются кнопкой **Подробнее** в отдельном окне. Краткое состояние остаётся рядом с выбором сертификата. Подробнее доступно и при ошибке чтения сертификатов.
- При включённом **Сохранять рядом с исходниками** строка отдельной папки скрыта. Отключение режима возвращает эту строку и ранее выбранный путь.
- Счётчик найденных и отмеченных актов, кнопки **Проверить и подписать** и **Отмена** остаются внизу окна. Высота строк учитывает шрифт, соседние строки слегка различаются по фону.

Предыдущая папка и режим сохранения по-прежнему запоминаются.

## Требования и установка

**[Скачать исходники ZIP](https://github.com/Alox1d/act-signer/archive/refs/heads/main.zip)**

| Компонент | Что требуется |
| --- | --- |
| Windows | Обычный рабочий стол Windows для интерфейса Windows Forms. Запуск приложения в Linux и macOS не поддерживается. |
| Windows PowerShell 5.1 | Используется `powershell.exe`, редакция `Desktop`, режим `STA`. PowerShell 7 (`pwsh.exe`) не является средой запуска приложения. |
| КриптоПро CSP | Настроенный криптопровайдер, совместимый с сертификатом, носителем и компонентами CAdESCOM. Условия лицензирования определяются установленным продуктом КриптоПро. |
| CAdESCOM | Локальные COM-компоненты КриптоПро ЭЦП: `CAdESCOM.Store`, `CAdESCOM.CPSigner`, `CAdESCOM.CadesSignedData` и используемые ими зависимости. |
| Windows Script Host | Доступный `cscript.exe` с движком JScript. Его использование должно быть разрешено политиками целевой Windows. |
| Сертификат | Сертификат ГОСТ Р 34.10-2012 с действующим сроком и доступным закрытым ключом. Фильтр допускает ГОСТ-2012-256 и ГОСТ-2012-512. |
| Носитель | Доступный КриптоПро ключевой контейнер. При использовании USB-токена нужны его совместимый драйвер и доступ из той Windows, где запущен ActSigner. |
| Папки | Чтение исходных файлов и запись в папку результата, включая журнал. Для запоминания папок нужен доступ к каталогу настроек текущего пользователя. |

Нужен именно Windows PowerShell 5.1 редакции `Desktop`. Параметры запуска описаны в [официальной инструкции Microsoft для powershell.exe](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_powershell_exe?view=powershell-5.1). Наличие подходящей версии в конкретной Windows нужно проверить; опубликованной матрицы совместимости ActSigner пока нет.

1. Установите и настройте компоненты по инструкциям производителя: [КриптоПро CSP](https://www.cryptopro.ru/products/csp), [загрузка КриптоПро ЭЦП и CAdESCOM](https://www.cryptopro.ru/products/cades/downloads), [документация КриптоПро ЭЦП Browser plug-in](https://docs.cryptopro.ru/cades/plugin). Для ActSigner используется локальный COM-интерфейс; открывать браузер для подписания не требуется.
2. При использовании токена установите подходящий драйвер и убедитесь средствами КриптоПро, что контейнер доступен текущему пользователю Windows. Сам ActSigner не устанавливает драйверы, не импортирует ключевые контейнеры и не регистрирует DLL.
3. На странице [репозитория ActSigner](https://github.com/Alox1d/act-signer) нажмите **Code**, затем **Download ZIP**. Полностью распакуйте скачанный архив. Сохраните взаимное расположение `Start.cmd`, `Sign-Acts.ps1`, модулей и вспомогательных файлов проекта.
4. Запустите **[Start.cmd](Start.cmd)**. Отдельный установщик, Python, Node.js и сборка проекта для запуска приложения не нужны.

Если установлен Git, вместо скачивания ZIP можно получить исходники командой:

```sh
git clone https://github.com/Alox1d/act-signer.git
```

Для загрузки установщиков на сайте КриптоПро может потребоваться учётная запись производителя.

Запуск ActSigner не требует повышения прав до администратора. Установка сторонних компонентов может требовать других прав согласно их инструкциям. `Start.cmd` задаёт `ExecutionPolicy Bypass` только для создаваемого процесса PowerShell и не меняет постоянную политику Windows. Если выполнение ограничено правилами организации, используйте согласованный в ней способ запуска. Документация Windows Script Host: [Microsoft CScript](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/cscript).

<a id="quick-start"></a>

## Запуск и выбор документов

1. Откройте `Start.cmd` из распакованной папки.
2. Укажите **Папку с актами**. Поиск включает доступные вложенные папки.
3. Проверьте **Сохранять рядом с исходниками**. На первом запуске флажок включён: подпись каждого акта попадёт в его собственную подпапку. Для отдельного комплекта снимите флажок и укажите **Папку результата**.
4. Проверьте сертификат. Если подходящий сертификат один, он выбирается автоматически; если несколько, выберите нужный. Кнопка **Подробнее** открывает владельца, издателя, отпечаток, сроки, источник и сообщения диагностики. Кнопка **Обновить** повторяет поиск сертификатов.
5. Нажмите **Найти акты**. Подходящие файлы без готовой целевой `.my.sig` отмечаются автоматически. Снимите отметки с документов, которые не нужно подписывать. Файлы с существующей подписью недоступны для повторного выбора.
6. Нажмите **Проверить и подписать**. Окно выбора закрывается. В консоли сначала проверяются соседние подписи; подтверждённые подписи этого PDF выбранным сертификатом пропускаются. Затем создаются необходимые новые подписи. Если криптопровайдер запросит PIN, вводите его в штатном окне КриптоПро или токена.
7. Дождитесь итоговых чисел и пути к журналу. Консоль остаётся открытой до нажатия клавиши.

Изменение папки или режима сохранения сбрасывает найденный список: нажмите **Найти акты** ещё раз. Закрытие окна выбора без нажатия **Проверить и подписать** не запускает подписание; выбранные папки и режим при этом запоминаются.

## Точные правила отбора актов

Поиск определяется **именем файла**, а не содержимым документа, номером договора, контрагентом или датой. В [Get-ActPlan](ActSigner.Core.psm1) используется шаблон без учёта регистра:

```regex
^Акт[_ ](?:оказанных[_ ]услуг|выполненных[_ ]работ)(?:\s*\(\d+\))?\.pdf$
```

Между основными словами допускается ровно один пробел или одно подчёркивание; их можно смешивать. Перед `.pdf` допускается номер в круглых скобках, с пробельными символами перед ним или без них.

| Имя | Попадёт в список |
| --- | --- |
| `Акт_оказанных_услуг.pdf` | Да |
| `Акт выполненных работ.pdf` | Да |
| `Акт_оказанных услуг(12).PDF` | Да |
| `Акт оказанных услуг (2).pdf` | Да |
| `Акт__оказанных_услуг.pdf` | Нет: два разделителя между словами |
| `Акт_оказанных_услуг_2.pdf` | Нет: номер должен быть в скобках |
| `Акт_оказанных_услуг_2026-01.pdf` | Нет: дополнительный суффикс |
| `Печатная_форма.pdf`, `Счёт.pdf`, `Документ.pdf` | Нет |

Печатная форма может копироваться вместе с актом, но не подписывается вместо него. Для других имён нужно изменить отбор в `ActSigner.Core.psm1` и проверить его на тестовых файлах; настройки пользовательского шаблона в окне нет.

Обход рекурсивный, список сортируется по относительному пути. Скрытые и системные элементы сами по себе не исключаются. Если отдельная папка результата находится внутри исходной, её поддерево не просматривается повторно.

Найденные внутри дерева файлы и каталоги с атрибутом `ReparsePoint`, включая символические ссылки и junction, пропускаются. Ссылка в самой выбранной исходной или выходной папке либо среди их существующих родителей вызывает ошибку. Недоступная папка может прервать поиск целиком: неполный список не следует считать полным комплектом актов.

**Лимит - 64 МиБ (67 108 864 байта) на каждый акт, каждый копируемый сопутствующий файл и новую подпись.** Размер проверяется при обработке. Файлы читаются в память, поэтому реальный расход памяти может превышать этот лимит. Для исходного акта проверяется начало `%PDF-`; полноценного анализа структуры, страниц или содержимого PDF в программе нет.

<a id="output"></a>

## Результат и размещение файлов

Имя целевого файла зависит от формата в окне. Например, при выбранном сертификате с фамилией Иванов стандартный формат создаёт **`signature_ivanov.sig`**.

| Режим | Исходный акт | Новая подпись |
| --- | --- | --- |
| Рядом с исходниками | `C:\Акты\Договор_001\Акт_оказанных_услуг.pdf` | `C:\Акты\Договор_001\signature_ivanov.sig` |
| Отдельная папка `C:\Результат` | Тот же акт относительно корня `C:\Акты` | `C:\Результат\Договор_001\signature_ivanov.sig` |

В режиме рядом копии документов не создаются: добавляются новые подписи в папки соответствующих актов и журнал в корне выбранной папки с актами. Для актов, которым создаётся новая подпись, в отдельной папке сохраняется структура подпапок и копируется PDF без изменения байтов. Уже подписанный выбранным сертификатом акт пропускается без новых копий; существующий результат указан в журнале. Если отдельная папка ещё не выбиралась, интерфейс предлагает `Подписанные_акты` внутри системной папки документов текущего пользователя (`MyDocuments`). Впоследствии восстанавливается сохранённая отдельная папка. Этот путь предлагается при отключении режима рядом с исходниками.

### Какие сопутствующие файлы копируются

В отдельный комплект также входят файлы из **той же папки, где лежит выбранный акт**, если имя соответствует одному из правил без учёта регистра:

| Правило | Пример |
| --- | --- |
| `signature*.sig` | `signature.sig`, `signature(1).sig` |
| Полное имя исходного PDF плюс `.sig` | `Акт_оказанных_услуг.pdf.sig` |
| Имя исходного акта без `.pdf` плюс `.sig` | `Акт_оказанных_услуг.sig` |
| `Печатная_форма*.pdf` | `Печатная_форма_001.pdf` |

Существующие `*.my.sig` и элементы `ReparsePoint` исключаются из этого набора. Пробел вместо подчёркивания в `Печатная_форма` этим правилом не предусмотрен. Квитанции, XML, ZIP и произвольные вложения с другими именами автоматически не копируются.

Связь сопутствующего файла с актом определяется только именем и расположением. При нескольких актах в одной папке шаблоны `signature*` и `Печатная_форма*` могут дать общий набор файлов. Эти правила копирования не устанавливают связь сопутствующего файла с актом. Отдельная проверка соседних подписей перед созданием новой описана [выше](#duplicate-check); она не меняет правила копирования. Оригинальный комплект документов следует сохранять отдельно от производного результата.

### Формат подписи

Код использует `SignCades` с типом **CAdES-BES** и признаком отсоединённой подписи. Возвращённая КриптоПро строка Base64 декодируется в бинарный файл подписи; это подпись семейства CMS/PKCS#7. Имя новой подписи определяется выбранным форматом. В подпись включается открытый сертификат подписанта. Криптографический интерфейс приложения: [ActSigner.CryptoPro.psm1](ActSigner.CryptoPro.psm1), вызовы CAdESCOM: [ActSigner.CryptoPro.js](ActSigner.CryptoPro.js). Принцип отсоединённой подписи: [официальный пример КриптоПро](https://docs.cryptopro.ru/cades/plugin/plugin-samples/plugin-samples-sign-detached).

Для проверки нужны **точные исходные байты PDF и соответствующий файл подписи**. Встроенная подпись PDF/PAdES, визуальный штамп и объединённый PDF не создаются. Расширение `.my.sig` - соглашение этой утилиты; требования принимающей системы к именам и формату нужно проверить отдельно.

## Сертификат и порядок подписания

### Как формируется список сертификатов

Программа рассматривает контейнерное хранилище КриптоПро (`100`) и личное хранилище текущего пользователя Windows `CurrentUser\My` (`2`). Фильтр оставляет сертификаты, для которых:

- `HasPrivateKey` сообщает о связи с закрытым ключом;
- алгоритм открытого ключа имеет OID `1.2.643.7.1.1.1.1` или `1.2.643.7.1.1.1.2`;
- срок действия уже начался и ещё не закончился по текущему времени Windows.

Одинаковые отпечатки объединяются. Ошибки чтения, неподходящие алгоритмы, отсутствие связи с ключом и сроки доступны в окне **Подробнее** рядом с выбором сертификата. Пустой список сам по себе не доказывает, что USB-носитель не подключён.

Выбор сертификата не хранится между запусками. При обновлении в том же окне предыдущий выбор сохраняется, если найдено единственное точное совпадение. Наличие сертификата в списке не проверяет правильность PIN и не гарантирует доступность ключа в момент подписания.

Один файл `.cer` без доступного закрытого ключа не позволяет подписать документ. PIN программа не принимает отдельным полем и не передаёт в командной строке. Число запросов PIN и кэширование авторизации определяются КриптоПро и носителем; один ввод на весь пакет не гарантируется.

### Как взаимодействуют PowerShell и CScript в версии 1.2

[ActSigner.CryptoPro.psm1](ActSigner.CryptoPro.psm1) запускает локальный процесс `cscript.exe` со сценарием [ActSigner.CryptoPro.js](ActSigner.CryptoPro.js). PowerShell отвечает за интерфейс, пути, чтение точных байтов PDF, проверку ответов и сохранение результатов. Сценарий JScript получает содержимое PDF через потоки, не принимает пути к документам и сам не читает или записывает файлы. CAdESCOM вызывается внутри дочернего процесса; закрытый ключ и PIN в протокол между процессами не передаются.

Обмен идёт через перенаправленные стандартные потоки ввода и вывода, без сетевого сервера. Используется версионированный построчный протокол `ACTSIGNER/1`: символы протокола ASCII передаются в UTF-16LE без BOM, двоичные данные кодируются Base64 порциями до 49 152 символов. Это кодирование, а не шифрование. Документы и подписи находятся в памяти локальных процессов, поэтому требования к защите Windows сохраняются.

Подписывающий процесс создаётся перед первым актом, которому нужна новая подпись, и сохраняет сеанс выбранного сертификата на оставшийся пакет. Это позволяет не сбрасывать процессное состояние CSP между актами, но не обещает единственного запроса PIN. Для полной проверки новой подписи запускается отдельный CScript. Чтение и математическая проверка соседней CMS выполняются локально через Windows CryptoAPI без подписывающего сеанса. Ошибка документа блокирует этот акт; отмена или сбой подписывающего сеанса останавливают пакет без автоматического повтора.

| Операция | Лимит ожидания |
| --- | --- |
| Подготовка компонентов (`CHECK`), поиск сертификатов (`DISCOVER`), выбор сертификата (`SELECT`) | 60 секунд на запрос |
| Создание подписи (`SIGN`) | 10 минут, включая ожидание PIN и проверки КриптоПро |
| Проверка новой подписи (`VERIFY`) | 10 минут |
| Локальная проверка соседней CMS | Ограничения размера, числа подписантов и суммарного хеширования, описанные выше |
| Штатное закрытие процесса (`CLOSE`) | 5 секунд, затем ограниченное завершение процесса |

На Windows x64 выбирается системный 64-разрядный CScript; при вызове из 32-разрядного процесса используется путь `Sysnative`. Автоматического переключения на x86 после ошибки нет. Это отличается от отдельной диагностической программы, которая намеренно сравнивает обе доступные разрядности.

### Что происходит с каждым выбранным актом

Обработка идёт последовательно. [Invoke-ActBatch](ActSigner.Core.psm1) выполняет следующие шаги:

1. Проверяет целевой путь; сохраняет защиту существующей целевой подписи от перезаписи.
2. Читает точный снимок PDF и проверяет соседние файлы подписей. Подтверждённая подпись выбранным сертификатом даёт `already_signed`; неопределённый результат блокирует новую подпись только этого акта.
3. Если нужна новая подпись, проверяет сопутствующие файлы, размеры, возможность записи и конфликты существующих копий; повторно сверяет исходник и соседние подписи.
4. Передаёт исходные байты криптографическому модулю. Подписывающий сеанс создаётся только при первой такой операции.
5. Проверяет новую подпись относительно тех же байтов и единственного выбранного подписанта.
6. Повторно проверяет SHA-256 исходника и состояние соседних подписей; при отдельной папке сохраняет копии и проверяет их хеши.
7. Ещё раз проверяет исходник и соседние подписи, затем сохраняет новую подпись через временный файл в той же папке без перезаписи.
8. Записывает итоговую строку журнала.

Криптографическая проверка выполняется в памяти до сохранения результата. Отдельного повторного вызова проверки для уже записанного `.my.sig` нет. SHA-256 в файловой логике нужен для контроля неизменности байтов и журнала; это не переключатель алгоритма электронной подписи ГОСТ.

В криптографическом модуле предусмотрен `CheckCertificate = true`. По [описанию КриптоПро](https://docs.cryptopro.ru/cades/reference/cadescom/cadescom_interface/icpsigner6checkcertificate), эта настройка включает проверку цепочки перед подписью, в том числе сроков использования закрытого ключа. Проверка не отключается ради продолжения пакета.

## Настройки, журнал и повторный запуск

### Запоминание папок

Настройки текущего пользователя сохраняются в:

```text
%LOCALAPPDATA%\ActSigner\settings.json
```

В JSON четыре поля: `SourceRoot`, `SeparateOutputRoot`, `SaveBesideSources`, `SignatureNaming`. Запоминаются папки, режим размещения и формат имени (`signer`, `document_signer`, `legacy`). Старые настройки без формата используют `signer`. На первом запуске режим рядом включён; явно выбранный режим отдельной папки сохраняется при следующих запусках. Закрытие окна без подписания тоже сохраняет настройки.

Временно недоступный сетевой или съёмный путь не стирается. Отсутствующий или повреждённый файл настроек приводит к значениям по умолчанию. Запись выполняется через временный файл и замену в том же каталоге. Ошибка сохранения не блокирует подписание, но выбор может не восстановиться в следующий раз. Реализация: [ActSigner.Settings.psm1](ActSigner.Settings.psm1).

Это обычный текстовый JSON с путями и форматом имени подписи, без шифрования. В нём нет PIN, ключей, сертификатов и сохранённого выбора подписанта. Для сброса предпочтений можно при закрытой программе переименовать `settings.json`, сохранив его при необходимости.

### CSV-журнал

При запуске пакетной обработки создаётся файл в **`<папка результата>\_ActSigner_logs`**. Для режима рядом папка результата совпадает с выбранным корнем актов. Имя журнала имеет вид `act-sign-yyyyMMdd-HHmmss-fff-xxxxxxxx.csv`.

| Поле | Содержимое |
| --- | --- |
| `Source` | Полный путь исходного PDF |
| `Destination` | Полный путь целевой подписи |
| `Hash` | SHA-256 прочитанного исходного PDF |
| `Thumb` | Отпечаток сертификата, выбранного для текущего запуска |
| `Status` | Статус обработки |
| `Message` | Пояснение или текст ошибки с этапом |
| `Time` | Время Windows в ISO 8601 с локальным смещением |

Журнал использует запятую как разделитель, UTF-8 с BOM и CRLF. Поля заключаются в кавычки, формулоподобное начало ячейки экранируется. Строки сбрасываются на диск по мере обработки.

| Статус | Значение |
| --- | --- |
| `signed_verified` | Новая подпись создана, проверена в памяти и сохранена |
| `exists_unverified` | Целевой файл занят; новая подпись не записана, собственная подпись выбранного сертификата не подтверждена |
| `already_signed` | Соседняя подпись проверена для этого PDF и выбранного сертификата; новый файл и копии не создавались |
| `error` | Ошибка акта; независимые акты продолжаются, если общий криптографический сеанс исправен |
| `cancelled` | Пользователь отменил криптографическую операцию; пакет остановлен |
| `not_processed` | До акта не дошло выполнение после остановки |

У `not_processed` поле `Hash` пустое. У `exists_unverified` оно заполнено, если PDF уже прочитан при проверке занятого пути, и пустое при пропуске без проверки. У `already_signed` указан SHA-256 проверенного PDF, а найденный файл подписи записан в `Message`. Поле `Destination` остаётся плановым путём новой подписи и при пропуске не означает, что этот файл создан. При ошибке хеш есть только если исходник уже удалось прочитать. Поле `Thumb` у `exists_unverified` **не устанавливает автора существующей подписи**: это по-прежнему выбор текущего запуска.

Существующие целевые подписи изначально не отмечены, но доступны для проверки. CSV содержит только выбранные акты. Подтверждённая собственная подпись получает `already_signed`; занятое имя чужой подписи не перезаписывается. Ошибка до запуска пакета может не создать CSV.

### Остановка и конфликты

**Ошибка одного документа оставляет результат `error` и позволяет обработать независимые документы. Отмена пользователем (`cancelled`) и неисправность общего криптографического сеанса останавливают пакет.** Автоматических повторов ввода PIN нет. Уже сохранённые подписи остаются, а оставшиеся выбранные акты получают `not_processed`. При принудительном закрытии консоли или `Ctrl+C` журнал может оказаться неполным.

Существующие `.my.sig` не перезаписываются. Если акт отмечен, содержимое подписи проверяется перед решением о пропуске. Само наличие файла не подтверждает валидность подписи, неизменность PDF или полноту отдельного комплекта. Такой пропуск не восстанавливает отсутствующие копии и сопутствующие файлы.

Существующая копия PDF или сопутствующего файла с тем же SHA-256 используется без перезаписи. Если байты отличаются, этот акт не подписывается; выберите новую папку результата для другой редакции документа. Не заменяйте PDF, для которого уже храните подписи.

Общей транзакции для папки или пакета нет. При ошибке после записи части копий они и созданные каталоги могут остаться. Контроль хешей и запись через временный файл уменьшают риск незаметного изменения, но не заменяют резервные копии и проверку полного комплекта.

## Диагностика CAdESCOM и разрядности

При `Store.Open 0x80004003`, пустом списке сертификатов или различиях между окружениями запустите:

```text
diagnostics\Check-CryptoPro.cmd
```

Запускать нужно в той же Windows и под тем же пользователем, где возникает ошибка. Папка `diagnostics` должна быть доступна для записи. Результат - **`diagnostics\ActSigner-diagnostics.txt`**. Повторный запуск перезаписывает предыдущий отчёт. Полная инструкция: [diagnostics/README.txt](diagnostics/README.txt).

Пакет собирает версии Windows, PowerShell и CLR, разрядность процесса, регистрацию `CAdESCOM.Store`, имя DLL и её числовые версии. Дополнительно читает количество сертификатов `.NET CurrentUser/My` с `ReadOnly | OpenExistingOnly` и сравнивает следующие COM-вызовы:

| ID проверки | Вызов |
| --- | --- |
| `CurrentUserReadOnly` | `Open(2, 'My', 0)` |
| `DefaultOpen` | `Open()` |
| `CurrentUserLocationOnly` | `Open(2)` |
| `CurrentUserMaximumAllowed` | `Open(2, 'My', 2)` |
| `MemoryReadOnly` | `Open(0, 'My', 0)` |
| `ContainerReadOnly` | `Open(100, 'My', 0)` |

Пробы выполняются через прямые вызовы PowerShell и независимо через CScript/JScript для доступных архитектур. Каждый вариант получает новый объект в отдельном процессе, лимит попытки - 30 секунд. Ошибка или таймаут не отменяет остальные попытки. Если на Windows x64 зависает каждая из 26 внешних попыток, весь запуск может занять около 13 минут.

Диагностика не создаёт подписи и не вызывает добавление/удаление сертификатов или экспорт ключей. Даже в пробе режима `2`, запрашивающего максимальные доступные права открытия, сценарий только читает `Count` и закрывает хранилище. Имена владельцев, отпечатки, содержимое сертификатов и имена контейнеров намеренно не включаются в отчёт. Вместо полных сообщений исключений сохраняются этапы, типы и HRESULT; непредвиденный вывод хостов дополнительно очищается от некоторых путей. Перед публикацией всё равно просмотрите текст целиком.

На обычной Windows x64 [Start.cmd](Start.cmd) выбирает 64-разрядный Windows PowerShell. Диагностика сравнивает его с x86 и CScript. Успех CScript при сбое PowerShell или различие x86/x64 помогает сузить поиск причины, но не устанавливает конкретный дефект. Разные `FileVersion` DLL x86 и x64 также не являются самостоятельным признаком неисправности.

Нет подтверждённого основания исправлять `0x80004003` отключением защит Windows, копированием случайных DLL или перерегистрацией COM по универсальной команде. Сначала нужен отчёт с результатами конкретных попыток.

### Windows в VirtualBox и USB-токен

КриптоПро CSP, CAdESCOM и драйвер используемого токена должны быть доступны **в гостевой Windows**, где запускается программа. Установка только на хосте не предоставляет гостевой системе её собственный COM-компонент.

VirtualBox предоставляет гостю USB-устройство через виртуальный USB-контроллер. Выбор устройства и USB-фильтры описаны в [официальном руководстве Oracle, USB Settings](https://docs.oracle.com/en/virtualization/virtualbox/7.2/user/working-with-vms.html). Подключайте нужный токен к гостю и проверяйте его видимость средствами КриптоПро внутри гостевой Windows; конфигурацию контроллера выбирайте по руководству для своей версии VirtualBox и гостевой ОС.

Общая папка с PDF и доступ к USB-токену - отдельные механизмы. Наличие актов в общей папке не подтверждает доступ к ключу. Общие папки VirtualBox описаны отдельно в [документации Guest Additions](https://docs.oracle.com/en/virtualization/virtualbox/7.2/user/guestadditions.html). Если сохранение рядом недоступно для записи, выберите отдельную доступную папку результата внутри гостевой Windows.

ActSigner не настраивает VirtualBox и не гарантирует совместимость конкретного токена, USB-контроллера или общей файловой системы. Сроки сертификатов проверяются по времени гостевой Windows, поэтому неверная дата также может исключить сертификат из списка.

## Данные, ключи и ограничения

### Что делает код с ключом и данными

Операции закрытого ключа выполняет КриптоПро. Программа не содержит команд экспорта закрытого ключа и не сохраняет PIN. Чтение открытого X.509-сертификата для фильтрации и отображения метаданных не является экспортом ключевого контейнера. Реальная защита ключа зависит также от носителя, настроек CSP, прав пользователя и состояния Windows.

В коде приложения нет загрузки PDF в веб-сервис, телеметрии или отправки документов на сервер. Полную работу без сети это не гарантирует: проверка сертификатов средствами Windows/КриптоПро может зависеть от доступа к ресурсам удостоверяющего центра. Если исходные или выходные папки синхронизируются облачным клиентом, файлы могут передаваться этим клиентом независимо от ActSigner.

| Артефакт | Что нужно учитывать перед передачей |
| --- | --- |
| Исходный PDF и его копии | Содержимое документа и возможные персональные или коммерческие данные |
| `.my.sig` и чужие `.sig` | Подпись может содержать открытый сертификат и сведения о подписанте; отсутствие закрытого ключа не делает файл анонимным |
| Основной CSV-журнал | Полные пути, отпечаток сертификата, хеш документа, время и текст ошибок |
| `settings.json` | Выбранные пути, которые могут раскрывать имя пользователя, клиента или сетевого ресурса |
| Диагностический TXT | Версии, архитектура, регистрационные сведения и количество сертификатов; автоматическое сокращение путей не заменяет просмотр перед публикацией |

**Не добавляйте в публичный репозиторий или Issue ключевые контейнеры, `.pfx`/`.p12`, PIN, реальные акты, подписи или необезличенные журналы.** Скриншот окна сертификата тоже может содержать ФИО, реквизиты и отпечаток. Для воспроизведения ошибки используйте документ без персональных данных.

### Границы текущей версии

- Поддерживается фиксированный набор имён PDF-актов и сертификаты ГОСТ-2012. Произвольные документы, RSA, ГОСТ-2001, разные подписанты для файлов одного пакета и шаблоны имён в интерфейсе не реализованы.
- Подписание последовательное, без фонового наблюдения за папками, планировщика и параметров командной строки для полностью автоматической обработки.
- PDF не анализируется как бухгалтерский документ и не проверяется на вредоносное содержимое. Контроль `%PDF-` не является полной проверкой формата.
- Проверка соседних подписей ограничена предотвращением повторной подписи выбранным сертификатом. Полного аудита истории подписей, восстановления исторической валидности и подтверждения полномочий подписанта нет.
- Добавляется время текущей Windows; сервер доверенных меток времени TSA не используется. Атрибут `SigningTime` и время CSV не являются независимым подтверждением времени.
- CAdES-T, CAdES-X Long Type 1 и архивные форматы подписи в текущем коде не создаются. Полный комплект данных для долгосрочной проверки автоматически не собирается.
- Нет интеграции с порталом ЭДО или изменения статуса приёмки акта. Создание локального файла подписи не выполняет действия в сторонней системе.
- Очень длинные пути и особенности сетевых/виртуальных файловых систем требуют отдельной проверки в целевой Windows. При ошибке длины пути используйте более короткий доступный путь.

Тесты не покрывают все ограничения и сбои файловой системы. Наличие проверки размера, блокировок или хешей в коде не означает, что все их граничные и конкурентные сценарии протестированы. Нативный UI-тест проверяет Windows Forms на вымышленных данных; он не импортирует КриптоПро и не создаёт подпись. Публичные автоматические тесты не используют настоящий PIN, драйверы и аппаратные носители. Реальные локальные проверки перечислены в начале README. Актуальный статус интеграции указан [в начале README](#status).

При подготовке диагностического пакета отдельно проверялись синтаксис, аргументы с кириллицей и `&`, вывод stdout/stderr, кодировка отчёта, таймаут с продолжением и имитации ошибок COM. Эти вспомогательные имитаторы не входят в репозиторий. Отдельно подтверждён диагностический факт: в тестовой Windows CScript открывает хранилища, прямой путь PowerShell возвращает ошибку. Полный пользовательский отчёт в репозитории не публикуется.

UI-тест запускается под Windows PowerShell 5.1 в режиме STA. Он сохраняет два снимка тестового окна и `measurements.json` в `ui-test-artifacts`; все имена документов и сведения сертификата в них вымышленные. Эти проверки охватывают указанные размеры окна, но не являются матрицей совместимости всех настроек DPI и шрифтов.

## Частые вопросы

### Почему акт с моей старой `.pdf.sig` всё ещё отмечен галочкой?

Наличие соседнего файла и подтверждённая подпись выбранного сертификата проверяются на разных этапах. **Найти акты** обнаруживает файлы. Статус **Проверить подписи (N)** означает, что подписи рядом найдены, но криптографическая проверка ещё не выполнена. **Проверить и подписать** перед созданием новой подписи проверяет точные байты PDF и выбранный сертификат. Подтверждённый повтор получает `already_signed` без нового вызова подписи.

В 1.4 этот этап обозначался как **Подписей рядом: N**, а кнопка называлась **Подписать**, что могло создавать впечатление готовности подписать уже подписанный акт. В 1.5 формулировки уточнены. Для совпадения не требуется одинаковое имя PDF и SIG. Файл с ожидаемым именем `.my.sig` отдельно защищён от перезаписи и сразу исключается из выбора даже без криптографической проверки; поэтому в итогах поиска он показывается как **Есть .my.sig**.

### Почему пакет остановился на `[1/6]`?

Если в заголовке консоли есть **Выбрать** или **Select**, нажмите **Esc**. Активное выделение текста может блокировать вывод прогресса. В версии 1.4 добавлена защита от случайного включения этого режима мышью; подробности выше в [описании исправления](#console-update).

Строка `[1/6]` означает начало обработки первого акта. Сообщение **Создана и проверена.** выводится после сохранения подписи и записи результата в журнал. Поэтому одна строка с номером не показывает, успело ли завершиться подписание. Если после Esc обработка не продолжается, проверьте через Alt+Tab, не ждёт ли КриптоПро ввода PIN, и прочитайте последнюю строку консоли. Итоги сохраняются в `_ActSigner_logs`; существующие `.my.sig` при повторном запуске пропускаются без перезаписи и повторной проверки.

### Почему нужного PDF нет в списке?

Проверьте [точное имя](#file-selection), выбранный корень и вложенные папки. Дополнительная дата, двойные разделители или другой суффикс не соответствуют шаблону. Элементы `ReparsePoint` пропускаются, отдельная выходная папка внутри исходной исключается. Программа не распознаёт акт по тексту.

### Почему сертификат виден в Windows, но отсутствует в ActSigner?

Важны текущий пользователь, доступная процессу регистрация COM, алгоритм, срок действия и связь с закрытым ключом. Нажмите **Подробнее** рядом с сертификатом, прочитайте сообщения и запустите [диагностику](#diagnostics). Наличие сертификата в другой программе или хранилище не устанавливает причину сбоя `CAdESCOM.Store.Open`.

### Почему нельзя снова отметить файл с `.my.sig`?

Существующий результат защищён от перезаписи. Проверки его валидности в интерфейсе нет. Для новой редакции документа используйте отдельный комплект и новую папку результата, сохраняя прежний PDF вместе с его прежней подписью.

### Можно ли использовать PowerShell 7 вместо Windows PowerShell 5.1?

Для запуска приложения используйте `Start.cmd`: `Sign-Acts.ps1` требует редакцию `Desktop`. Проход отдельных тестов на PowerShell 7 не означает поддержку этой среды для приложения.

### Будет ли PIN запрошен один раз?

Это зависит от носителя и CSP. В программе нет собственного хранилища PIN и управления кэшем токена. Отмена штатного запроса останавливает пакет; автоматического повторного ввода нет.

### Почему подпись не отображается внутри PDF?

Результат отсоединённый: файл SIG лежит отдельно, PDF не редактируется. Проверяющей программе нужно передать оба файла. Поддержку формата и требования к имени уточняйте для конкретной принимающей системы.

### Решает ли программа проблему старой чужой подписи или приёмки на портале?

Нет. Она создаёт новую локальную подпись текущего подписанта, не проверяет чужую историю подписания, не получает доверенную метку времени и не выполняет действия на портале ЭДО.

### Как сообщить об ошибке без персональных данных

Для [Issue в этом репозитории](https://github.com/Alox1d/act-signer/issues) полезны:

1. Версия ActSigner или commit, версия и разрядность Windows, наличие виртуальной машины.
2. Версии CSP и CAdESCOM, если известны; модель носителя без серийного номера, если проблема связана с ним.
3. Шаги, ожидаемый и фактический результат: при запуске, поиске, чтении сертификатов, подписании или сохранении.
4. Точное название этапа и HRESULT, например `Store.Open`, `0x80004003`, `NullReferenceException`.
5. Просмотренный и при необходимости дополнительно обезличенный `ActSigner-diagnostics.txt` для COM-сбоев.
6. Для файловой ошибки - вымышленные имена и структуру папок с теми же особенностями пути, размер тестового файла и режим сохранения.

Не прикладывайте настоящий акт, сертификат, `.my.sig`, полный CSV, снимок окна с реквизитами, ключевой контейнер или PIN. Если ошибка воспроизводится только на реальных документах, сначала опишите условия текстом. Из сообщения и путей удалите ФИО, ИНН, названия клиентов, имена пользователей и сетевых ресурсов.

## English summary

**ActSigner** is a Windows PowerShell 5.1 utility for batch signing Russian PDF service/work completion acts with **CryptoPro CSP**, **CAdESCOM** and GOST R 34.10-2012 certificates. It uses filename-based recursive discovery, a Windows Forms selection dialog, detached **CAdES-BES / CMS** signatures saved as `signature_<surname>.sig` by default, optional output copies, remembered folders and CSV logs. Source PDF bytes are preserved. The scripts do not export private keys or store PINs.

Version 1.5.1 separates CMS SignerInfo identity, exact-byte mathematical verification and certificate trust. Expired foreign certificates do not gate a separate own signature when identity and mathematics are confirmed. Confirmed selected-certificate signatures skip without key access. Uncertainty blocks that document; independent documents continue. Cancellation and unusable shared signing sessions stop separately. Selected-certificate checks and full CAdESCOM verification of new signatures remain in place. Real GOST signing, full verification, key-free repeat, both multi-signer orders, changed PDF, damaged SIG and unchanged source hashes were verified on one Windows 11/CryptoPro configuration. Public automated fixtures are synthetic; private documents and logs are excluded.

Version 1.5.0 adds background GitHub Release updates. The bundled launcher validates cached files and launches immediately without foreground HTTP calls. Complete checksummed packages activate on the next launch; the previous version and bundled fallback remain available. Release integrity is based on HTTPS repository trust and SHA-256, not an independent publisher-signing certificate. The UI now distinguishes pending neighbor-signature checks from creation of a new signature.

New signature filenames can use the signer surname, document name plus surname, or the legacy `.my.sig` format. The preference is remembered. Missing surnames use a short certificate identifier; existing files are never renamed or overwritten.
